# T08 — jasper/control/ (37 files, 18,959 LOC) @ 2d571e6b8

## A. Tile mandate & verdict

**Mandate:** the always-on local HTTP control plane — one `/state` aggregate, the
mutation endpoints, the privileged-action broker, and the resident health/liveness
loops that no other daemon hosts.

**Verdict: three tangled systems in one package.** (1) an HTTP server + route mixins,
(2) a cross-daemon *read* aggregator (`state_aggregate` + `audio_health` +
`airplay_health` + `system_metrics` = 8,231 LOC, 43 % of the tile), (3) a privileged
*write* boundary (`restart_broker` + 13 direct `systemctl` sites that bypass it). The
package is coherent at the "always-on daemon" altitude and incoherent at every level
below: there are two schema builders for overlapping facts (`/state` and
`/system/snapshot`), three renderings of the same fan-in/outputd probes, five resident
loops in two shapes, and four postures for "restart a unit."

## C. Top findings

### C1 — Blocker · a polkit-denied privileged action returns HTTP 200 and lies, **live at HEAD**
`handlers/system.py:499-514`, `handlers/aec.py:354`, `debug_control.py:75`,
`aec_endpoints.py:369`, `server.py:1095`, `shairport_supervisor.py:400-421`,
`system_supervisor.py:509-519`.

`jasper-control` runs `User=jasper-control`, `NoNewPrivileges=true`
(`deploy/systemd/jasper-control.service:115`), so every `systemctl` mutation is
polkit-mediated. These call sites use `subprocess.Popen(...)` (or `await proc.wait()`
discarding `returncode`), so a denial or `masked`/`not-found` exit is invisible: the
only failure they can report is a *spawn* `OSError`.

**And the drift is real today.** `LOCAL_SOURCE_AUDIO_REFRESH_UNITS` (server.py:133,
from `local_sources.registry`) contains `jasper-usbsink-volume.service`, which is
**not** in `restart_broker.MANAGED_UNITS` and **not** in
`deploy/polkit/49-jasper-control.rules`:

```
$ python3 -c "...; print(sorted(set(local_source_audio_refresh_units()) - (MANAGED_UNITS|START_ONLY_UNITS)))"
['jasper-usbsink-volume.service']
```

So `POST /system/restart/audio` and `POST /system/audio-quality` fire
`systemctl try-restart … jasper-usbsink-volume.service`, get denied, and answer
`{"ok": true, …, "try_restart_units": [… "jasper-usbsink-volume.service"]}`.
Same shape in `shairport_supervisor`: `_tick` logs
`event=shairport.wedge_detected action=restart` and increments `restart_count`
(→ `/state.resilience.shairport`) **before** `restart_shairport()` swallows the rc —
`shairport.restart_failed` only fires on an exception, never on rc≠0.

The correct pattern is 40 lines away in the same file: `server._run_oneshot_start`
(709-753) and `_start_diagnostics_refresh` (176-215) both read `returncode` and
surface it. `tests/test_control_server_system.py:762-769` asserts only the argv
(`popens == [["systemctl","reboot"]]`) — the denial path has **no** behaviour pin.

**Fix:** route every unit mutation in `jasper/control/` through
`restart_broker.manage_units` / `reset_then_manage` (they already return `ok`/`rc` and
audit); add one test that asserts a rc≠0 unit action yields a non-2xx and an
`event=…_failed` line; add a test asserting `local_source_audio_refresh_units() |
local_source_park_units() ⊆ POLKIT_MANAGE_UNITS` (the existing
`tests/test_polkit_jasper_control.py` only pins polkit↔broker equality, not
"units the endpoints actually touch").

### C5 — Should-fix · `debug_control` does an unlocked read-modify-write of a shared env file
`debug_control.py:56-62`: *"Mirrors `server._atomic_rewrite_env`; duplicated (not
imported) to avoid a circular import with the server module."* The stated reason is
wrong — `server._atomic_rewrite_env` (server.py:633) is itself a one-line call to
`jasper.atomic_io.locked_update_env_file`, which has no cycle. The duplicate uses
`web._common.read_env_file` + `write_env_file` with **no advisory lock**, so a
`/debug` POST racing the expiry timer (or `apply_for`) can lose keys in
`/var/lib/jasper/debug.env`.
**Fix:** `locked_update_env_file(debug_mode.DEBUG_FILE, updates, mode=0o644)`; delete
`_atomic_write` and the comment. Same swap for `usb_gadget_forensics.py:13`.

### C7 — Should-fix · `/state` spawns 3–4 subprocesses per build on a 415 MB target
`state_aggregate._wifi_guardian_snapshot` (773) → `wifi_guardian_state.snapshot()` runs
**two `nmcli` + one `journalctl -n 200 -o json`** every uncached `/state`
(1 s TTL, `STATE_RESPONSE_CACHE_TTL_SEC`), plus one `busctl` for `mpris`. Its own
docstring admits *"a wedged nmcli or journal holds a `/state` aggregation for up to
[3 s] per call."* The fact it reports comes from a **`Type=oneshot` that runs once at
boot** — it cannot change between polls. `/state` is polled by the landing page, `/rooms`
(7 s), `/sources` (4 s) and `/system` (5 s). AGENTS.md: *"no short-lived Python in hot
paths … the Pi Zero 2 W (415 MB) is a supported target."*
**Fix:** cache the wifi-guardian snapshot keyed on the stash file's mtime (it already
stats the file), or on a 60 s TTL like `SOURCE_AVAILABILITY_TTL_SEC`.

### C8 — Should-fix · the handlers/ split increased coupling instead of reducing it (#4114 in flight)
`handlers/__init__.py` claims *"The server factory retains request guards, route tables,
and dispatch ordering. These mixins own only the route bodies."* Measured:

- **215** `_server.<name>` reach-throughs across 6 mixins, over **79 distinct names**.
- Of those, `logger` ×45, `log_event` ×25, `asyncio` ×18, `subprocess` ×14, `time` ×2,
  `json` ×1 — the mixins go through `server` to reach **stdlib modules**
  (`_server.asyncio.TimeoutError`, `_server.json.JSONDecodeError`,
  `handlers/voice.py:31,42`). Triple-hop private reach exists too:
  `_server._aec_endpoints._TOGGLE_TO_TOKEN` (`handlers/aec.py:61`).
- server.py carries **~30 names imported solely as `# noqa: F401 - route-mixin
  dependency exports`** (server.py:52-114) plus **19 pure delegator functions**
  (563-859) that only forward to `_aec_endpoints` / `_state_aggregate` / `_volume_ops`.
- `handlers/_base.py` re-declares the factory's attribute contract as `Any` stubs
  because mypy can't see through the nested class.

`handlers/measurement.py` is the proof this is avoidable: 82 LOC, imports
`measurement_hold` directly, **zero** `_server.` uses.
**Fix (mechanical, big win):** mixins get `logger = logging.getLogger(__name__)`, import
stdlib and `log_event` directly, and import `aec_endpoints` / `state_aggregate` /
`volume_ops` by name. That removes ~108 of 215 reach-throughs, the 19 delegators, and
most of the `noqa: F401` block — server.py drops several hundred lines.

### C9 — Should-fix · `/state` has one builder but no schema owner, and nine publish mechanisms
`state_aggregate._get_state` (1085-1425) is the sole assembler of the 341-line literal —
good. But there is no declared contract, no version field, and no consumer validation.
The daemons publish into it by **nine different mechanisms**:

| # | mechanism | example |
|---|---|---|
| 1 | UNIX STATUS socket, JSON | fan-in, outputd (`uds._local_status_json`) |
| 2 | UNIX line protocol | voice `STATUS`, mux `STATUS` (`uds._voice/_mux_socket_command`) |
| 3 | CamillaDSP websocket | `_camilla_status` |
| 4 | DBus via `busctl` subprocess | `mpris.shairport_playing` |
| 5 | in-process module singleton | `shairport/grouping/system_supervisor.snapshot()`, `debug_control`, `measurement_hold` |
| 6 | on-disk state/env files | `identity_state`, `camilla_recover_state`, `bootloop_guard_state`, `transport_park`, transit, grouping.env, tools.json |
| 7 | **journal scraping** | `wifi_guardian_state._last_guardian_event`, `_multiroom_cascade_snapshot` |
| 8 | read-only SQLite | `_conversation_history_state` |
| 9 | `systemctl show` + HTTP child | `service_states`, `ha_status_cache` |

Two structural consequences: (a) `/state` carries `fanin` and `outputd` **verbatim**
*and* re-derived projections of the same two probes under `audio_graph.fanin` /
`audio_graph.outputd` (`_audio_graph_state:239-327`) — the same fact spelled twice in one
response; (b) `/system/snapshot` (`handlers/system.py:106-200`) is a **second** schema
builder carrying overlapping keys (`transport_park`, `outputd`, `home_assistant`,
`speaker_name`, `audio_quality`, `usb_latency`, `voice_provider`) composed by an
entirely different code path, with `audio_health.py` building a **third** rendering of
the same fan-in/outputd probes (`signal_path`, `current_stream`, `_usb_timing`).
`audio_health.SCHEMA_VERSION = 1` is emitted at :2309 and read by nobody (grep over
`jasper/`, `deploy/assets/`, `tests/` finds only the definition, the emission, and a
literal `1` in a test).
**Fix:** don't build a schema framework. Do two concrete things — delete the
`audio_graph.fanin`/`audio_graph.outputd` re-projections in favour of the verbatim
sections, and have `_get_system_snapshot` compose its overlapping keys from
`_get_state`'s sections rather than re-reading.

### C10 — Nit → Should-fix · "the single mediated systemctl boundary" is not true, and the tree says so twice
`server.py:2253` (in `main`): *"The privileged restart broker: jasper-control **is the
single mediated systemctl boundary**."* `restart_broker.py:41`: *"**NOT brokered, by
design** — this is the door for non-root clients, **not the tree's only systemctl**."*

**Recount (tree-wide, `jasper/`, tests excluded):** 458 lines mention `systemctl`; **74**
are actual argv sites (`grep -rn "['\"]systemctl['\"]"`). Of those, ~28 are read-only
probes (`is-active` / `is-enabled` / `show`) which need no broker, ~10 are generic
wrappers, and **~36 are state-changing**. **13 of those 36 live inside
`jasper/control/` itself** — the daemon that hosts the broker. The previous audit's "96"
appears to have counted mentions, not sites; the honest number is **74 sites / ~36
mutating / 13 inside the tile**.

**Judgment: the docstring's rationale is sound; the *comment in `main()` is false* and
the 13 in-tile sites are not defensible.** Root CLIs and read-only probes are correctly
outside the broker. But "we already hold the polkit grant so we can call directly" gives
up the allowlist check, the audit line, and the `reset_then_manage` retry budget — which
is exactly how C1 became possible.
**Fix:** delete the `main()` claim; convert the 13 in-tile mutating sites to
`manage_units`. Then the sentence becomes true for state-changing verbs.
