# T03 — assistant integrations (40 files, 13,043 LOC) @ 2d571e6b8

## A. Tile mandate & verdict

**Mandate:** everything the assistant reaches *outside the speaker* — transit/weather/
smart-home/maps/calendar answers for the voice loop, the OAuth account registries behind
them, and two paid text-LLM surfaces (background research, correction tuning advisor).

**Verdict: four systems in one tile, only one of which is coherent.**

| system | state |
|---|---|
| `transit/` registry + subway/bus/citibike | coherent, over-documented; the tile's best-organised corner |
| weather / home_assistant / google_routes | three independent one-file clients, no shared HTTP/retry/cache seam |
| `accounts.py` + `google_creds.py` | **two copies of one registry** (~90 LOC verbatim duplication) |
| `research/` + `calibration_agent/` | **two independent OpenAI text-LLM stacks** (~1,000 LOC of parallel provider/store/surface) |

The registry abstraction the transit corner earned was not reused by the two LLM corners,
which each grew their own provider layer with different env vocabularies, different HTTP
libraries (httpx-async vs `urllib.request`), and different persistence stories.

**On the parent's extensibility.md premise:** `docs/extensibility.md` does **not** say
subway/citibike/bus should live under `transit/providers` (only line 198 names "the transit
pattern"). The import-cycle hazard is real and documented in code, not docs:
`jasper/citibike.py:47` imports `.transit.base`, which executes `transit/__init__.py:88`,
which imports `providers/citibike.py`, which lazy-imports `jasper.citibike` back
(`transit/providers/citibike.py:28-34` comment). The split is 3 top-level runtime clients +
3 provider adapters + `_mta_stations.py` + `tools/{subway,bus,citibike}.py` = 4 files per
mode. Consolidating each mode into one `transit/providers/<mode>.py` would delete the cycle
and the lazy-import comments that defend it.

**Earns-its-keep (tried to cut, could not):**
- `transit/_mta_stations.py` — a real SSOT win; both consumers named, parse memoised.
- `research/scheduler.py` retention + `prune_terminal`'s "never prune unannounced" rule — the bound and the correctness constraint are both load-bearing on a 1 GB always-on box.
- `home_assistant.probe_status` cache — documented incident (dashboard polls every 5 s against a dead HA); `verify_ssl` in the key is a real bug fix.
- `bus.BusClient._fetch_for_stop_cached` — "don't poison the cache on error" is subtle and right.
- `citibike.normalize_station_name` — 90 lines of regex that exist because TTS reads "41 St" wrong; not derivable.

**Secrets (non-negotiable 3) — clean.** Every credential path checked: BusTime key rides
in the query string and every interpolation goes through `transit/base.scrub_secrets`
(`nyc_bus.py:131,136,246,281`; `bus.py:405,414`). Google Routes / OpenAI / HA keys ride in
headers, never in a logged URL. `AdvisorModelSettings.api_key` is `field(repr=False)`
(`model_client.py:66`). Nothing in the tile writes a key to `/state`, doctor output, or an
error message. One residual to watch: `google_creds.py:283` logs the google-auth
`RefreshError` verbatim — that carries the token endpoint's error body, not the secret, but
it is the only unfiltered provider-exception interpolation left.

**HTTP/retry/timeout discipline — every call is bounded**, but by three idioms:
`httpx.Client` per-call (transit providers, geocode, citibike), long-lived
`httpx.AsyncClient` (bus, weather, HA), and `urllib.request` (`model_client._post_json`).
Retry exists in only two of nine clients: `weather._get_json` (2 attempts, 429/5xx only)
and `spotify_router` (`_RETRY_BACKOFF_SEC`, transient-only). `openai_research.complete`
polls `while status in {queued,in_progress}` with no attempt ceiling — bounded solely by
the scheduler's `asyncio.wait_for(300s)` (`scheduler.py:_run`), safe today because that is
the only construction site.

**Observability gaps:** `citibike`, `google_routes`, `google_tokens`, `home_assistant` have
doctor checks (`cli/doctor/integrations.py:40,100,145,202`); **subway, bus and weather have
none**. `/state` carries transit packs, HA, spotify and research; no weather/subway/bus
health. Event vocabulary is dotted (`transit.*`, `ha.*`, `research.*`,
`calibration_agent.*`) except weather, which is flat (`weather_geocode`,
`weather_http_error`, `weather_response_error`) — 11 flat vs 139 dotted repo-wide.

**Tests:** healthy. No source-text or docstring assertions; only two private-name pins
(`spotify_router._evict_failure_log_cache`, `research.catalog._validate_providers`), both
justified. `tests/test_weather.py:778` asserts log *text* (`"event=weather_response_error"
in caplog.text`) — prose-adjacent, should assert structured fields.
`tests/test_calibration_agent_correction_advisor.py:48` `importlib`-loads
`scripts/tuning-llm-live-check.py` to call its private `_demo_session()`; the docstring
justifies it (provenance lockstep) and I'd keep it. Unpinned real failure modes: the
`active_transit` per-provider fault isolation (`transit/__init__.py:280-300`) and
`ActiveTransit.aclose` swallowing — both are the "one bad provider must not kill the voice
daemon" guarantee and neither has a direct behavior pin.

## D. If I could do one thing

Collapse the two paid-LLM stacks into one: make `jasper.research`'s provider registry the
only OpenAI text client, delete `model_client.resolve_settings` + `_post_json` + its 4 dead
env knobs, and let `calibration_agent` supply only its prompt package and strict schema.
That removes ~350 LOC, one HTTP idiom, and the three-way model-resolution split
(`JASPER_RESEARCH_OPENAI_MODEL` / `JASPER_TUNING_LLM_MODEL` /
`JASPER_CALIBRATION_ADVISOR_MODEL`).
