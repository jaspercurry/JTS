# T11 — `jasper/correction/` (28 files, 13,872 LOC) @ 2d571e6b8

## A. Mandate and verdict

**Mandate (as written, `__init__.py:7-11`):** own the *room*-correction target/strategy policy, the
multi-position measurement state machine, and the evidence bundle — consuming the shared measurement
kernel `jasper.audio_measurement` and the shared DSP-apply seam (`sound.graph_carrier` +
`dsp_apply`) rather than re-implementing either.

**Verdict: mostly one coherent system, with three foreign bodies inside it.**
The room half (session → strategy → target/spatial/variance_cap → artifacts/bundles → status/envelope)
is genuinely one system with a defensible boundary against `audio_measurement/` and `active_speaker/`
— the CamillaDSP emission path is *not* duplicated (it goes through `graph_carrier.reemit` +
`apply_dsp_config`, same as `sound/` and `active_speaker/`), and `correction/bundles.py` layers a room
schema over `audio_measurement/bundles.py`'s neutral manifest exactly as that module's charter says.
But:

1. **Two live level-ramp implementations** sit in the same `MeasurementSession`: the bespoke
   `autolevel.py` (what production actually runs) and `level_match.py` (kernel-backed, *unreachable*
   from Room). This is the "second copy of the machinery" the tile asks about — and it is inside the
   package, not across the `correction/` ↔ `active_speaker/` line.
2. **`level_match.py` is not correction's**: `jasper/web/correction_crossover_backend.py` — the
   *crossover* backend — imports `LevelLockStore`/`LevelMatchSession` from it. It is a shared
   adapter parked in the wrong package.
3. **`fir_runtime.py` + the `future_fir` gate ladder** (~450 LOC across four modules) is scaffolding
   for a feature that does not exist and has no design.

Functions ≥ 100 LOC: **24**. Classes ≥ 300 LOC: 3. Prose: 15% (713 comment + 1,380 docstring lines).
