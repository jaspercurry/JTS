# T25-deploy-assets-2 — management-UI JS/CSS (43 files, 15,504 LOC)

## A. Tile mandate & verdict

Mandate: the browser-side behaviour + page CSS for a dozen jts.local management
pages (room correction, active-speaker/crossover, sound-profile pieces,
rooms/grouping, bluetooth, wake/wake-corpus, sources, system-status audio
sections, tools, chat, google/transit/voice/airplay chrome).

Verdict: **two tangled systems, not one.** (1) The system-status / chat /
tools / bluetooth / wake / sources / google / transit / voice family is a
genuinely coherent, well-migrated set — every file imports the shared
`http.js`/`dialog.js`/`dom.js`/`escape.js` primitives correctly, uses
`startPolling`, hides with the `hidden` attribute, and reads as one system.
(2) The `/correction/` + `/sound/room|crossover|bass/` measurement family
(`correction/js/main.js`, `crossover/main.js`, `cloud.js`,
`frequency-chart.js`, `measurements.js`, `bass/main.js`) is itself three
generations of the same feature bolted together: the newest pieces
(`measurements.js`, `bass/main.js`, `cloud.js`) correctly consume the shared
layer and each other; the two oldest and largest files
(`correction/js/main.js`, 3450 LOC; `crossover/main.js`, 1093 LOC) predate
several shared-module promotions and still hand-roll their own polling, DOM
building, mic-capture worklet, WAV encoding, and canvas charting — duplicating
primitives that exist one directory away and, in the mic-capture/WAV case,
have already drifted from them.

## D. If I could do one thing

Migrate `correction/js/main.js`'s mic-capture (worklet + WAV encode),
polling, and chart-drawing onto `measurement-audio.js` / `startPolling` /
`frequency-chart.js` — the same primitives its own sibling files
(`measurements.js`, `cloud.js`, `bass/main.js`) already use correctly. That
one migration removes ~400 duplicated lines, closes the WAV-encoding bit-drift,
and turns the tile's one straggler file into the same modern shape as
everything else in it.
