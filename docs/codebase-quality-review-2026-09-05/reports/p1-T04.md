# T04 — sources & volume (32 files, 14,990 LOC)

## A. Tile mandate and verdict

**Mandate:** decide *which* source is audible (mux + source_state/source_events + source_intent
lifecycle + the four renderer packages) and *how loud* it is (the volume coordinator/owner/persistence/
observers/diagnostics stack).

**Verdict: four systems, not one — three coherent, one tangled.**

| system | owner | state |
|---|---|---|
| source arbitration ("latest start wins") | `mux.py` + `source_state`/`source_events` | coherent, explicit, well-observed |
| source lifecycle (on/off, systemd, RF-kill) | `source_intent.py` + `local_sources/` | coherent, one root writer, one intent file |
| Bluetooth control plane | `bluetooth/` | coherent; carries one write-only orphan |
| **volume** | **5 modules + 1 file + 1 /run snapshot** | **tangled — see below** |

`transport_coherence.py` is in this tile by name only; it is fan-in/outputd topology (§E).

### "Latest source wins" — is the state machine explicit and observable?

Mostly yes. `_State.started_seq` is a monotonic process-local sequence, `_pick_winner` is 8 lines,
`_record_source_observation` is await-free and atomic, and every transition emits
`event=source.handoff_start` / `source.handoff` / `mux.source_reconcile` with `reason=` and per-source
`observation` + `started_seq` in STATUS. There is **no named state enum** — mode is derived from
`_test_fanin_label` / `_manual_source` / `_winner` — and `_pending_auto_target` (the failed-handoff retry
latch) and `_winner_age_ticks` reach **no** surface, so a box parked on a failed handoff shows
`winner: null, active_source: idle` with only `last_handoff.result` as a clue (F-nit).

### Polling loops and cadence

| loop | cadence | cost/tick |
|---|---|---|
| `Mux.run` patrol | 1.0 s, alert-woken, `EVENT_BACKED_PROBE_SEC=5 s` defer for the 2 subprocess probes | fan-in UDS + file read; busctl/bluealsa-cli ≤ 1/5 s |
| `VolumeObserver._run` | 1.0 s, **flat, no defer, no alerts** | mux UDS ×2, **busctl fork ×2 + bluealsa-cli fork**, camilla read — every second, forever (F1) |
| `_pairable_floor_watch` | 60 s on a cached session | 2 D-Bus reads (one redundant) |
| `VolumeBridge` | event-driven (`add_reader` on mixer FDs) ✔ | 0 idle |
| `VolumeBridge._retry_declined` | **unbounded**, 5 s ceiling | 1 POST/5 s forever (F7) |

## D. If I could do one thing to this tile

Make volume **one** system with **one** loop: land the reconciler deletion `VolumeOwner._settle` already
justifies (F2), and make `VolumeObserver` probe only the active source (F1). That removes one of the two
answers to "what should the fader read", ~200 LOC, and 2–3 subprocess forks per second on a 415 MB target —
and it is the precondition for splitting `VolumeCoordinator` (F8) without moving the tangle around.
