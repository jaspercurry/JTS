# T17-cli-2 — jasper/cli/ (half 2: tuning CLIs + round_views), 25 files, 8978 LOC

## A. Tile mandate & verdict

Operator-facing CLIs for the crossover-tuning / active-speaker-commissioning
workflow (`crossover_prescriber`, `angle_capture`, `seat_level`, `round`,
`round_views/*`), plus a grab-bag of unrelated maintenance CLIs that happen to
live in the same directory (`wake_enroll`, `noise_capture`, `system_soak`,
`sound`, `correction_bundle`, `google_auth`, `route_latency_harness`,
`audio_hw_validate`, `measurement_mic`).

**Verdict: one coherent system (the tuning-CLI family, ~60% of the LOC) plus
several unrelated single-purpose tools sharing a directory.** The tuning
family (crossover_prescriber, angle_capture, seat_level, round, round_views/*)
is genuinely excellent: thin argparse wrappers, all business logic lives in
`jasper.active_speaker.crossover_v2.*`, a real shared refusal/exit-code
vocabulary (`_refusal.py`), and round_views/ is a clean table-driven dispatch
(`_FAMILIES` tuple + uniform `add_parser(sub)` contract per module — this
*is* the table the brief asks whether it should be). The non-tuning CLIs are
each fine in isolation but don't share the tuning family's scaffolding, and
that's the tile's biggest finding: `jasper/cli/_report.py` (a JSON
report/atomic-write helper built for exactly this) exists and is consumed by
exactly one caller (`round_views/_common.py`) in the whole tile.

## C. Top findings

1. **Should-fix | crossover_prescriber.py:218,239,377,379; angle_capture.py:481-568; seat_level.py:730; round.py:96,277; sound.py:68,110; correction_bundle.py:105,121,136,165; system_soak.py:431; route_latency_harness.py:549,645,815; round_views/delay.py:123,167** — `jasper/cli/_report.py` (`render_report`/`write_report`: sort_keys, atomic write, `allow_nan=False`) exists precisely for "the tuning CLIs' JSON report writer" and is consumed by exactly one caller in the tile (`round_views/_common.py`). Every other JSON-emitting file hand-rolls `json.dumps(x, indent=2, sort_keys=True)` at 15+ call sites — angle_capture.py's four calls don't even agree with each other on `sort_keys`. **Fix:** route file writes through `_report.write_report` (fixes finding 5's atomicity gap for free) and stdout prints through `render_report`.

2. **Should-fix | audio_hw_validate.py:262** — `logging.basicConfig(level=logging.INFO, format="%(message)s")` sits inside `run_audio_hardware_validation`, a library-shaped function called directly by 4+ tests (`tests/test_audio_hw_validate.py`), not inside `hardware_main` (the actual entry point). This is the exact anti-pattern three sibling CLIs (`angle_capture`, `seat_level`, `crossover_prescriber`) explicitly comment that they avoid ("in `main`, not at import/library-call, because configuring the root logger elsewhere imposes that choice on every importer, the test suite included"). It's also issue #4085 item 10's 4th CLI (with `angle_capture.py:981`, `seat_level.py:708`, `sound.py:190` — all justified as needing an INFO floor `_logging.configure_verbose_logging` doesn't offer, except `sound.py`/`audio_hw_validate.py` which don't even reuse `CLI_LOG_FORMAT`). **Fix:** move the call into `hardware_main`; consider a `configure_event_logging()` helper in `_logging.py` so the 4-5 near-identical justification comments collapse to one.

3. **Should-fix | audio_hw_validate.py:241-436** — `run_audio_hardware_validation` is a 196-line function branching on `profile` into two unrelated validation flows (outputd-stability: ~25 lines; chip-AEC: ~150 lines with readiness-gate → preflight sample → probe-gate → chip-readback/poll → final sample → artifact build). **Fix:** split into `_run_outputd_stability_validation(...)` and `_run_chip_aec_validation(...)`, called from a slim dispatcher.

4. **Should-fix | wake_enroll.py:242-246,634-655** — `systemctl(action, unit)` calls `subprocess.run(cmd, check=True)` with no timeout, then `main`'s `finally` block calls `systemctl("start")` to restore the voice daemon on exit, catching only `CalledProcessError`. A hung `systemctl start jasper-voice` blocks the CLI forever with wake response down and no bound — no self-recovery. Contrast `jasper/web/_service_state.py:14`'s own `systemctl(*args, timeout: int = 8)`. **Fix:** add `timeout=` and catch `subprocess.TimeoutExpired` alongside `CalledProcessError`.

5. **Should-fix | system_soak.py:431** — `path.write_text(json.dumps(artifact, ...) + "\n")` is a non-atomic write of a soak artifact that can represent up to 2 hours of sampling (`MAX_DURATION_SEC`). This tool runs *on the box being soak-tested*; an OOM-kill or Ctrl-C mid-write loses the whole run with a truncated/corrupt file on disk. Same root cause as finding 1 (crossover_prescriber.py:225 `out.write_text(blob)` and route_latency_harness.py:547,645,815 share it). **Fix:** `_report.write_report` (atomic via `jasper.atomic_io.atomic_write_text`).

6. **Should-fix | google_auth.py:40** — `def main() -> None:` takes no `argv`, unlike every other CLI in the tile (`def main(argv: ... | None = None) -> int`, 20+ instances). This is very likely *why* it has zero tests (confirmed: `tests/test_web_google_setup.py`'s one "google_auth" hit tests the web wizard, not this file) — every other CLI's tests call `module.main([...])` directly. Also duplicates `spotify_auth.py` (T17-cli-1)'s ~20-line "paste the redirect URL" instruction block near-verbatim. **Fix:** `def main(argv: list[str] | None = None) -> int`, `parser.parse_args(argv)`, return an int instead of relying on `sys.exit`; add a `tests/test_google_auth.py` covering the name-validation, missing-config, and code-extraction branches at minimum.

7. **Nit | correction_bundle.py:105,121,136,165** — bare `json.dumps(payload, indent=2, sort_keys=True)` on payloads carrying computed dB values (`group_delay_ms`, `required_headroom_db`, RMS deltas) with no `allow_nan=False`. Python's `json.dumps` silently emits literal `NaN`/`Infinity` tokens (invalid JSON) on a degenerate computation instead of raising. `_report.render_report` already guards this.

8. **Nit | sound.py:81-132 (`_cmd_render_flat_cutover`)** — this is, per its own docstring, "the ONE entry every writer uses" (`deploy/install.sh`, `jasper-audio-hardware-reconcile`, `jasper-output-topology-reset`), but `tests/test_sound_cli.py` has exactly one test and it covers only `reconcile-current-dsp`; `test_audio_hardware_reconcile.py` exercises this path only by shelling out to a faked binary, not by asserting on the CLI's own `--json` shape or its `OutputTopologyError` → exit-1-and-write-nothing refusal branch.

9. **Earns-its-keep | round_views/ subpackage** — the brief asks whether the one-file-per-verb pattern should collapse into a table. It effectively already is one: `__init__.py`'s `_FAMILIES` tuple + each module's uniform `add_parser(sub)` contract *is* the table; the per-file split is justified because each view (frequency, distortion, delay, seats, sweeps...) holds meaningfully distinct domain logic, not just boilerplate variation. Collapsing further would just relocate the same code under worse names. Tried to find a merge candidate here and couldn't — leave it.

10. **Earns-its-keep | noise_capture.py:69-80** — explicitly imports `CHANNELS`, `SAMPLE_RATE_HZ`, `require_root`, `systemctl`, etc. from `wake_enroll.py` with a comment stating why ("avoids drift between two near-identical recording CLIs") instead of re-deriving them. Correct instinct, and the reused names are all public (no `_foo` reach).

11. **Nit | wake_enroll.py:170-178 vs noise_capture.py:150-196 (`stream_to_wav`)** — both hand-roll the identical "write via `.tmp` + `os.replace`" atomic-WAV-write idiom independently (one-shot bytes vs. streamed frames). Small, but a shared `atomic_wave_writer` context manager would remove the duplication noise_capture's own comment (finding 10) says it's trying to avoid.

12. **Nit | crossover_prescriber.py:377** — `Path(args.out).write_text(json.dumps(result, indent=2, sort_keys=True) + "\n")` inside `_cmd_stage` (the verb that *banks* a prescription) is non-atomic — same class as finding 5, but here it's writing the record of a state transition the tool explicitly cares about being observable.

13. **Should-fix (test gap, not new) | crossover_prescriber.py has no test file matching its own name** — false alarm on first pass; it's covered by `tests/test_crossover_v2_prescriber_status.py` (39 tests, imports `jasper.cli.crossover_prescriber as cli`). Recording this only so the synthesis doesn't independently rediscover and misreport it as a gap — the naming convention (`test_crossover_v2_*` for a `jasper/cli/*` subject) is itself worth a Nit: it cost real time to find.

14. **Nit | seat_level.py, angle_capture.py comment weight** — both carry very long (5-15 line) comments justifying the `logging.basicConfig`-in-`main` pattern, each restating the same reasoning `crossover_prescriber.py` already stated first. Not narration (each is genuine why-content), but four near-identical paragraphs is exactly what a shared `_logging.configure_event_logging()` helper (finding 2) would let collapse to one docstring.

15. **Earns-its-keep | measurement_mic.py** — brief flagged CLIs with no pyproject entry point as orphan candidates; this one is deliberate (`python -m jasper.cli.measurement_mic`, called from `deploy/bin/jasper-aec-reconcile:1198`, tested indirectly via `tests/test_aec_reconcile.py`). Not orphaned — confirm this for the orphan sweep.

## D. If I could do one thing

Make every JSON-emitting CLI in this tile go through `jasper/cli/_report.py` for both file writes and stdout prints (finding 1). It's a mechanical, low-risk change that simultaneously fixes the non-atomic-write resilience gap (findings 5, 12), the NaN-safety gap (finding 7), and the sort_keys inconsistency (angle_capture.py) — one existing module, already built for this, already proven in round_views/.
