# T14-2 — `jasper/active_speaker/` root, tile 2 (28 files, 24,200 lines)

## A. Tile mandate and verdict

**Mandate as written:** "commission an active speaker" — compile a declared
crossover into a protected CamillaDSP graph, stage/load it, ramp it audible under
operator confirmation, measure it, and grade the result.

**Verdict: four tangled systems, not one.** The tile holds (1) a *declared-contract
validator* stack (`driver_safety`, `crossover_declaration`, `crossover_preview`,
`test_signal_plan`), (2) a *graph staging + guarded-load* stack (`staging`,
`startup_load`, `commission_ramp`, `safe_playback`, `calibration_level`,
`setup_status`), (3) a *measurement session* stack (`crossover_v2_flow`,
`commissioning_capture`, `capture_geometry`, `crossover_alignment`,
`crossover_level_run`, `flat_spec*`, `branch_chain`), and (4) a *lab-arm CLI driver*
(`arm_walk`). They share only the package directory and a house dict shape.
The package root is **106 flat modules** whose intended hierarchy is already spelled
into filenames — `commissioning_*` ×14, `crossover_*` ×8, `driver_*` ×6,
`measurement_*` ×5, `commission_*` ×3 — so a newcomer cannot tell `commission_load`
from `commissioning_run` without opening both. **The layout that would tell them:**
`driver/` (safety, protection, pad, base_trim, acoustics, prompt, design_draft,
declaration_vocabulary — 7,017 lines, one caller cluster), `staging/` (staging,
startup_load, startup_hold, commission_load, commission_ramp, commission_wiring,
path_safety, safe_playback, calibration_level — 8,596 lines), `spec/` (flat_spec,
flat_spec_views, branch_chain's DSP half), `lab/` (arm_walk, angle_capture*), with
`crossover_v2/` unchanged and `commissioning_*` folded into `crossover_v2/` or
`staging/` by which of the two it actually serves.
