# p1-T14-4 — `jasper/active_speaker/` root, quarter 4 (28 files, 24,208 LOC)

## A. Tile mandate and verdict

**Mandate (as written):** turn a declared multi-way speaker design into a proven
CamillaDSP graph — emit it, measure it, evidence it, apply it.

**Verdict: five tangled systems, not one.** The 28 files split cleanly into five
concerns that share only a directory: (1) **graph emission** (`camilla_yaml`,
1 file / 4,028 LOC); (2) the **v1 commissioning evidence lane**
(`commissioning_{evidence,service,apply,verification,host,isolated_producer}` +
`measured_candidate` + `level_trim` = 8,547 LOC here, 21,667 with its siblings);
(3) **DSP fit/grade math** (`linearization_fit`, `delta_probe`, `branch_*`,
`driver_acoustics`); (4) **measurement-session runtime** (`seat_level_ramp`,
`session_volume_plan`, `program_admission`, `attempts_loop`, `model_error_store`);
(5) **operator-declaration glue** (`declaration_vocabulary`, `driver_pad`,
`driver_safety_prompt`, `topology_tone`, `commission_wiring`, `revalidation`).
Plus `wizard_client` (an HTTP client for the web wizard) and `bench/` which belong
to neither.

**The 107 root files are a flat bag.** Nothing in the layout tells a newcomer that
`measured_candidate.py` and `measured_crossover_candidate.py` are *rival* candidate
models, or that `commissioning_*` is a different engine from `crossover_v2/`.
Proposed hierarchy (names are the concerns already present, not new machinery):
