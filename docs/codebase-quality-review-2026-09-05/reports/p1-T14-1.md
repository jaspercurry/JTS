## A. Tile mandate and verdict

**Claimed mandate** (`__init__.py:5`): "Active-speaker crossover commissioning substrate."

**Verdict: not one system — five, plus a web adapter layer, all flat in one 107-file /
94,582-LOC directory** (plus `crossover_v2/`, 63 files / 44,203 LOC, which *is* a
subpackage and proves the pattern works). My tile alone contains: (1) the declaration
data model (`profile`, `design_draft`), (2) the CamillaDSP graph emit/verify contract
(`runtime_contract`, `graph_evidence`, `environment`), (3) the commissioning state
machine + durable stores (`commissioning_run`, `commissioning_evidence_store`,
`commission_load`, `bringup`, `startup_hold`), (4) measurement/analysis view
(`measurement_document`, `frequency_view`, `crossover_eligibility`, `bench/`), and (5)
web/HTTP orchestration (`web_commissioning`, `commissioning_coordinator`).

**The hierarchy tells a newcomer nothing.** `commission_load` / `commissioning_run` /
`commissioning_admission` / `commissioning_coordinator` / `commissioning_evidence_store`
sit alphabetically adjacent and share no layer. A newcomer cannot tell that
`runtime_contract` owns the boot-time graph selector, `staging` owns the config
directory, and `environment` owns a *second* graph classifier, because all three are
peers in one `ls`.
