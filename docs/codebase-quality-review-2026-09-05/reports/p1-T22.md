# Tile T22 — c/jts-ring-ioplug, experiments/, wake_training/

## A. Mandate & verdict

Three unrelated systems sharing a tile, each internally coherent:
1. **c/jts-ring-ioplug** — the C half of the cross-process SHM ping-pong ring
   (ALSA ioplug + pure writer/reader core) that is the sole audio transport
   between renderers/CamillaDSP/outputd on a ring-eligible box.
2. **experiments/usb-turntable** — a safety-gated CLI wrapper + vendored
   serial-protocol library driving the lab measurement turntable; despite
   the path, it is a real production dependency of `jasper/active_speaker`.
3. **wake_training/** — a small, side-effect-light, laptop-only package of
   shared data-prep helpers for the offline wake-word training pipeline.

Verdict: not one system — three independently well-run ones. All three are
unusually mature for their size (rigorous bounds/overflow discipline, dense
cross-language test pinning, exhaustive behavior tests). This is some of the
highest-quality code seen in the repo; findings below are mostly nits.

## C. Top findings

1. **Should-fix** | `experiments/usb-turntable/` (whole dir) | Real production
   dependency (rsync'd to the Pi by `deploy/lib/install/python-runtime.sh:206`,
   hardcoded at `/opt/jasper/experiments/usb-turntable/jts_turntable.py` in
   `jasper/active_speaker/arm_walk.py:104`) living under a directory literally
   named `experiments/`. Already flagged, unresolved, in
   `docs/DEEP-AUDIT-2026-08-25.md:194`. **Full promotion into `jasper/` is not
   free**: `arm_walk.py`'s `TurntableMover` deliberately drives it as a
   subprocess, never an import (`arm_walk.py:326`, "Never an import") — the
   process boundary is the safety mechanism (a wedged serial write is killed
   by the subprocess timeout without taking the measurement-loop process with
   it, and the CLI's `--confirm-*` flags are a harder-to-bypass gate than a
   Python kwarg would be). Promoting would also need the vendored
   `usb_turntable` package pulled into `jasper`'s install graph and
   `[tool.setuptools.packages.find]` widened. **Cleanest fix**: rename the
   directory (e.g. `tools/usb-turntable/`) to fix the naming-honesty
   complaint without disturbing the working subprocess boundary — update the
   4 hardcoded path references (`python-runtime.sh`, `arm_walk.py`, mypy
   `files=`, `pyproject.toml` ruff exclude).

2. **Nit** | `c/jts-ring-ioplug/ring_writer_bench.c`, `ring_reader_bench.c` |
   Compiled in CI (`.github/workflows/tests.yml:549` `make test bench
   plugin`) but invoked by no script, systemd unit, or doc — grep-confirmed
   across `jasper/ rust/ c/ deploy/ scripts/ tests/ .github/ docs/`. Matches
   the independent P0 orphan-sweep finding (`p0-orphans.md:254`). Read both
   files fully: each is a self-documented, deliberate on-hardware smoke tool
   (`ring_reader_bench.c:1-16` — "the on-Pi interop proof the golden-layout
   test cannot cover: real bytes through a real mmap, the Rust RingWriter
   feeding the C reader core"). Verdict differs from the sweep's tentative
   "delete": **keep** — they cover a real gap (cross-language byte-level
   interop that no CI test exercises) at the cost of two cheap compiles.
   Cleanest fix, if anything: one line in `docs/audio-paths.md` telling a
   future reader they exist and how to run them by hand.

3. **Nit** | `c/jts-ring-ioplug/test_ring_core.c` (4033 lines, 65 tests) |
   One flat file spans 5 concerns: create/attach/reclaim transaction races
   (~lines 1066-1696), playback pointer/alias (~479-1065), capture core
   (~1881-3204), and the pacing governor alone is ~830 lines (3205-4022).
   Concrete split: `test_ring_pace.c` for the pacing block, sharing the
   existing harness (`CHECK`, path/lock cleanup, `owned_tmp_path`) via a
   small internal header. Not urgent — the shared `main()` sequencing and
   harness make this a pure navigation win, not a correctness one; every test
   is independently meaningful (no example-cluster bloat to trim).

4. **Nit** | `experiments/usb-turntable/vendor/usb_turntable/cli.py` +
   `__main__.py` | The vendored package's own CLI (`python -m usb_turntable
   turn --direction cw 5`, no power preflight, no travel envelope, no confirm
   gate) is never invoked anywhere in JTS — `jts_turntable.py` is the only
   sanctioned entry point and never imports `usb_turntable.cli`. This is
   correct vendoring discipline (the snapshot's `aggregate_sha256` is
   pinned by `test_usb_turntable_experiment.py:216-235`, so trimming files
   would require an upstream re-sync, not a local edit) — flagging only so a
   future reader doesn't mistake `python -m usb_turntable` for a supported
   JTS entry point. No action needed; the module boundary already makes this
   safe (JTS code path never reaches it).

5. **Earns-its-keep** | ring golden-layout contract | The header offsets,
   channel/slot ceilings, sample-format enum ids, and lock-contract constants
   are independently spelled in C (`jts_ring_shm.h` `_Static_assert`),
   Rust (`rust/jasper-ring/src/layout.rs` golden-layout test), and Python
   (`jasper/ring_assets.py`) — a naive SSOT read would flag 3 spellings of
   one fact. Tried to find a collapse and could not: there is no shared-type
   mechanism across a C/Rust/Python FFI boundary over raw shared memory, so
   the 6 tests in `tests/test_ring_slot_ceiling_pin.py` (each diffing two of
   the three spellings, by regex against the literal source, not by
   behavior) are the actual mechanism holding this together, not a
   redundancy to remove. Leave it.

6. **Nit** | `c/jts-ring-ioplug/jts_ring_shm.c:561-706` `ring_mapping_open` |
   145-line function (one create/attach/reclaim retry loop with 3 nested
   outcome branches). Concrete split: extract the torn-reclaim branch
   (~659-698, the `stat`+`unlink_owned_ring` sequence) into
   `static int reclaim_torn_ring(...)`. Low priority: the function is a
   single linear retry loop (not deeply nested), and is exercised by ~10
   dedicated tests in `test_ring_core.c` (`test_stale_reclaimer_a_...`,
   `test_owned_reclaim_*`, `test_simultaneous_first_open_waits_...`) that a
   split would need to keep passing unchanged — real but small risk for a
   readability-only gain.

7. **Earns-its-keep** | bounds/overflow handling, C ring core | Explicitly
   asked to check: `JTS_RING_MAX_SLOT_BYTES` (65536) bounds the create-path
   `ftruncate` derived from `period_frames × channels × sample_width`
   (`jts_ring_geometry_validate`, `jts_ring_shm.c:187-219`); `n_slots`
   2..16, `channels` 2..8, `rate` fixed 48000 — all rejected before any
   syscall touches the filesystem. The one non-trivial overflow site,
   `jts_ring_pace_refill_tokens` (`jts_ring_shm.h:489-496`, elapsed-ns to
   token conversion), carries a written proof of its bound across the full
   `u64` input range in the header comment and is exercised end-to-end by
   `test_pace_refill_overflow_bound` (marks at 1s/5d/180d/1y/`UINT64_MAX`,
   asserting strict monotonic increase — a wrap would show up as a value
   that went down). No gaps found.

8. **Earns-its-keep** | wake_training/feature_bank.py SSOT | Both
   `scripts/_build_wake_feature_bank.py` and
   `scripts/_build_wake_negative_feature_bank.py` import `wake_training.

9. **Earns-its-keep** | wake_training packaging | Confirmed off-Pi:
