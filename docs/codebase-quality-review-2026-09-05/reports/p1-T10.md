# T10 — `jasper/cli/doctor/` (30 files, 19,723 LOC)

## A. Mandate and verdict

**Mandate:** one root one-shot health tool — a verdict layer over readers homed with
their subsystems, plus the probes that need root/hardware, emitting one typed row per
check to a CLI report and a JSON contract the `/system` dashboard renders (ADR-0233
rules 1–4).

**Verdict: one coherent system, well past the point of being one *readable* one.**
The infrastructure spine (`_registry` / `_harness` / `_evidence` / `_cli` / `_shared`
+ `jasper/doctor_contract.py`) is genuinely good — 1,065 LOC of it, one schema, one
roster, one memo, no dead defs. The 24 domain modules are 18,658 LOC of verdict logic
that has kept growing without anyone asking whether a one-owner box needs 172 rows.
The measured problems are not architectural drift; they are **scale** (172 rows, both
surfaces print all of them), **evidence re-reads the memo already exists to prevent**
(~22 reads of one file per run), and **ADR-0233 rule 5 unshipped** (`jasper-deploy-health`,
the third health tool the ADR retires, is still live in `install.sh` and `deploy-to-pi.sh`).

### Earns-its-keep (tried to cut, could not)

- **The typed contract is one schema and it is right.** `jasper/doctor_contract.py`, 97
  lines, stdlib-only, deliberately importable by `jasper-control` without dragging in
  the 24 check modules. `CheckResult.__post_init__` enforces the closed status set,
  *requires* a reason on every warn/fail, and rejects `speaker_silent` on an `ok`.
  `check_row`/`summarize` are the single row and summary builders — CLI, `--json`,
  `--out`, the dashboard table and the crash/timeout/skip/config-error rows all go
  through them. **One schema, no second shape.** The 722 domain `REASON_*` constants
  are per-domain closed vocabularies, and `tests/test_doctor_registry.py` enforces
  closure by AST: symbolic-only reasons, no string literals, lower_snake_case, unique,
  used, and declared in exactly one module. Nothing to cut here.
- **`_evidence.py`'s memo, `_registry.py`'s roster, `_harness.py`'s lanes.** 665 LOC
  that would each otherwise be scattered per-module. Import-time `ValueError` for an
  unrostered module is a structural guard with real teeth (PR #4043 mutation-verified it).
- **`resilience.py`.** `check_supply_voltage` explicitly refuses to add a second
  `vcgencmd` poller and reads jasper-control's sampler instead. This is what ADR-0233
  rule 2 looks like when it lands.
- **No dead code.** An AST sweep of all 361 module-level defs/classes/constants against
  `jasper/ rust/ c/ deploy/ scripts/ tests/ .github/` found **zero** orphans beyond the
  one wrapper in F9. The registry test plus ruff keep it that way.
- **Resilience posture.** Every `subprocess`/socket/HTTP call in the tile is bounded
  (`_run` defaults to 5 s; the four raw `subprocess.run` sites pass 2–5 s; the child-
  interpreter PCM probes and `aplay` probes carry their own kill timers). No unbounded
  loop, no bare `except: pass`. The `_bounded_dir_size` walk is hard-capped on entries
  **and** depth and reports a floor when truncated.

## Answers to the four asked questions

**Does doctor shell out to probes daemons already publish?** Mostly **no**, and this is
the healthy half. Only 14 distinct binaries across 26 `_run` sites (`amixer` ×5,
`systemctl` ×2, `ip`, `hostname`, `iw`, `ss`, `lsusb`, `lsmod`, `journalctl`,
`bluetoothctl`, `aplay`, `snapclient`, `shairport-sync`, `systemd-analyze`), and
ADR-0233 rule 2 *sends* those here deliberately. The daemon-published facts go through
`evidence.fanin_status()` / `outputd_status()` / `unit_states()`. ADR-0226 is about hot
and restart paths; a root one-shot forking `amixer` is in scope for the doctor. The
genuine rule-2 breach is on the **other** side: `state_aggregate._wifi_guardian_snapshot`
forks `nmcli` twice + `journalctl` once **per `/state` call** — see Cross-tile.

**Is the typed output contract one schema?** Yes — see Earns-its-keep. The only
contract defects found are two rows saying `ok` while their prose says "skipped"
(`boot_config.py:35`, `audio_runtime_ring.py:544`).

**PR direction (#4102 / #4082 / #4043 / #4099 / #4127 / #4128):** the **structural**
wave is right and largely done — #4043 (one module roster, `order=`/`group=` deleted),
#4082 (`__init__` 1029→478, 272 re-exports → 0, 385 test call sites re-homed), #4102
(478→32 + `_harness`/`_cli`, 11 underscore names off the public surface, mypy baseline
entry deleted). All three merged today; each *removed* more than it added. The three
**open** PRs point the wrong way by comparison:
- **#4128** (absent USB-mic preference is `skipped`, not `fail`) — correct, and correctly
  scoped to the contract.
- **#4099** (drift check defers to the boot-loop guard) — a real double-report fixed by
  consuming the guard's own reader. Right instinct; it patches around `drift.py`'s
  hand-copied `StartLimitAction` table (F10) rather than sourcing it from `FragmentPath`,
  which the file's own comment already names as the intended replacement.
- **#4127** (omit both crossover-v2 checks on streambox) — **the direction to push back
  on.** The defect is that one reader takes >15 s and is called twice; the fix omits the
  rows on the one profile where they don't apply and leaves the full speaker paying the
  15 s stall *twice*. Memoizing the reader is a smaller diff that fixes both boxes.

**Right-sized for a one-owner box, or a scrolling report?** **A scrolling report, on
both surfaces.** `_cli.render` prints every one of the 172 rows unconditionally
(`for r in results: print(...)`) — no `--fails-only`, no `--quiet`, no severity filter
in argparse. `deploy/assets/system-status/js/actions.js:126-152` renders every row into
one table with no collapse. On a healthy box that is 172 green lines to find the
`all checks passed.` at the bottom. `--watch` (one summary line + first-fail name) is
the only right-sized view and it exists — it just isn't the default shape. Combined
with the 600 s unit budget and 87 rows that cannot fail, the tool has drifted from
"one-shot verdict" toward "inventory of everything that was observed".

## D. If I could do one thing

Land ADR-0233 **rule 5** — the `--core` registry subset with lazy per-module imports —
and use it twice: delete `deploy/bin/jasper-deploy-health` (900 LOC, both call sites),
and make `--core` the CLI's **default** shape with full `--all` behind a flag. That
turns 172 rows into a short verdict, retires the third health tool, and gives the 87
warn-only rows a home (the `--all` inventory) instead of a demotion argument.
