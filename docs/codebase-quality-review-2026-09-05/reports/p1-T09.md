# T09 — multiroom / peering / accessories

## A. Tile mandate and verdict

**Mandate:** three unrelated opt-in subsystems that happen to share the word
"other device": `multiroom/` = one speaker's role in a snapcast bond (config →
plan → derived env files → systemd/CamillaDSP applies); `peering/` = multi-Pi
wake arbitration over private multicast; `accessories/` = HID/BLE remotes
bridged into jasper-control HTTP.

**Verdict: three separate systems, not one.** They share no code, no file, no
vocabulary — the only coupling is that `/rooms/` renders both multiroom and
peering. `accessories/` is the healthiest package in the tile (one clear
mandate, ADR-0225 honoured, small files). `peering/` is a well-factored pure
core with a **dead mDNS/status half bolted on**. `multiroom/` is one coherent
system with one un-decomposed god function (`reconcile.main`, 864 LOC) and a
31 %-prose problem.

## E. Cross-tile pointers

- **Role-state SSOT (answering the brief):** there is **one** requested-role SSOT
  (`/var/lib/jasper/grouping.env`, parsed only by `multiroom/config.py`) and **one**
  effective-role fact (`/var/lib/jasper-grouping/effective-role.json`, written only
  by `reconcile._write_follower_status`, read only via `effective_role.py`). The 6
  other role-derived files (`snapcast-args.env`, `grouping-outputd.env`,
  `grouping-voice.env`, `grouping-airplay.env`, 3 camilla stashes) are single-writer
  projections of those two — a legitimate 2-layer model, not duplication.
  `control/grouping_supervisor.py` and `fanin` re-derive nothing; both import
  `multiroom.config`. **One consumer uses the wrong layer:**
  `jasper/web/correction_crossover_flow.py:158` gates on the *requested*
  `is_bonded_follower(cfg)` where every other consumer uses
  `effective_role.effective_local_sources_park_reason` — a refused-and-fell-back-to-solo
  speaker gets the bonded copy. UI-copy only today, but it is the one drift point.
- **`jasper/config.py:955-956`** re-spells `/run/jasper-control/peering.sock`
  instead of importing `peering.config.PEERING_UDS_PATH` (comment at :950 admits it).
  Two spellings of one socket path.
- **`jasper/identity.py:42,49`** sources `PEER_ID_FILE` from `peering.config` — the
  per-install machine identity is owned by the peering package. Ownership looks
  inverted; see finding 4.
- **`scripts/_sync_measure_audio.py:29`** and `multiroom/sync_measure.py:104` are two
  `read_wav_mono` implementations. Documented as deliberate (different numeric

- **`deploy/systemd/jasper-grouping-reconcile.service:31` `TimeoutStartSec=6346`**

### Brief's specific questions

- **Subwoofer deletion (ADR-0236):** clean in this tile. `ALLOWED_CHANNELS`
  (`config.py:66`) has no `"sub"`; no `GROUPING_CROSSOVER_HZ` / `_MAINS_HIGHPASS` /
  `_SUBWOOFER_PRESENT` / `bond_has_subwoofer` / `DAC_CONTENT_SUB_HZ` anywhere in the
  repo; `jasper/bass_management.py` is gone; ADR-0126 is marked Superseded; the
  multiroom docs carry no wireless-sub prose. **No leftovers found.**
- **Live vs speculative:** multiroom is **live, not speculative**, despite PLAN.md's
  "Later". `deploy/install.sh:1564` `systemctl enable jasper-grouping-reconcile.service`
  runs on every install and every boot on both the full and streambox profiles
  (`systemd-units.sh:1244,1308`); `install_grouping_unit_files` (:667) always ships the
  units; only `snapserver`/`snapclient` are gated (binaries apt-installed on opt-in by
  `provision.py`; units ship disabled). Peering is installed-but-off (`install.sh:2278,2323`
  installs only the Avahi template; the daemon no-ops when `peering.env` says off).
  Accessories are always-on (`jasper-input` enabled on both profiles). So "Later" means
  *no new multiroom features*, not *unshipped code*.
- **Household PSK:** **there is none in this tile.** Peering carries no shared secret —
  the multicast wire is unauthenticated JSON (`transport.py:106-158`) and
  `peering.env` is mode 0644 with no credential. Nothing in `multiroom/`, `peering/`
  or `accessories/` reads, writes, or logs a secret; every env file the tile writes is
  0644 and explicitly documented as secret-free (`reconcile.py:182,1123,1579`). The
  household credential the brief refers to lives in `jasper/control/household_credential.py`
  (imported by `control/grouping_supervisor.py:78`) — a different tile. **No secrets
  leak found here.**
- **ADR-0225 one-interpreter rule:** honoured. See finding 15.
