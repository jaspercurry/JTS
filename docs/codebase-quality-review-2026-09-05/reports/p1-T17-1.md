# T17-cli-1 — jasper/cli/ (half, excl. doctor/AEC) — 24 files, 8979 LOC

## A. Tile mandate

Operator-facing CLI entry points that are neither `doctor/` nor AEC: tuning/measurement
instrumentation (`active_speaker`, `measure`, `null_door`, `basic_profile`, `audition`,
`bass_extension_bench`, `active_speaker_emit_bench`, `round_views/*`), occasional household
config doors (`control_token`, `declare_geometry`, `airplay_mode`, `output_topology_reset`,
`spotify_auth`, `audio_config`), a Bluetooth link-tuning oneshot (`wiim_remote_ce`), a
USB-gadget volume daemon (`usbsink_volume_main`), and wake-model R&D tooling (`wake_review`,
`wake_score`).

**Verdict: one coherent package, three unconverged failure-vocabularies, by design, not
tangle.** `_refusal.py`'s own docstring scopes itself to "the tuning CLIs" — and indeed only
part of the tile uses it (`measure`, `null_door`, `declare_geometry`, `round_views/*`,
partially `basic_profile`/`audition` via exit-code constants only). `wake_review`/`wake_score`
use their own `ERROR: ...` + exit-1/2 convention (a different, older R&D domain). `audio_config`,
`airplay_mode`, `control_token`, `wiim_remote_ce`, `usbsink_volume_main` use plain
print+return-int with no shared vocabulary at all — legitimate, since they're reconciler/systemd
callers reading `key value` lines, not JSON-refusal consumers. Nobody should assume
`_refusal.py`'s codes apply tile-wide.

## E. Cross-tile pointers

- `jasper/cli/crossover_prescriber.py:1363` and `jasper/cli/angle_capture.py:981` (sibling
  tile) carry the identical `logging.basicConfig(level=logging.INFO, format=CLI_LOG_FORMAT)`
  line as `audition.py`/`measure.py` here — fix once, apply to all four.
- **Confirmed dead:** `jasper-web` (`jasper.web.spotify_setup:main`) and `jasper-sound-web`
  (`jasper.web.sound_setup:main`) pyproject entry points. `deploy/jasper-web.service` runs
  `python -m jasper.web`, and `jasper/web/__main__.py:247-436` calls
  `spotify_setup.make_server()` / `sound_setup.make_server()` directly — never `main()`. No
  script, doc, or unit invokes the installed `jasper-web`/`jasper-sound-web` binaries anywhere
  in the repo. Safe to delete both `main()` functions and their `[project.scripts]` lines.
  (`jasper/web/` package, not this tile — flagging for whoever owns it.)
- **Refuted as orphan:** `jasper-wake-corpus-web`. Its own module docstring documents direct
  standalone invocation (`sudo /opt/jasper/.venv/bin/jasper-wake-corpus-web`) as a deliberate
  alternative to the lazy-loaded route inside `jasper/web/__main__.py`; both paths are real.
- **Refuted as orphan:** `jasper-aec-sweep-config`. It is an intentionally SSH/operator-invoked,
  stdlib-only door ("gives operators and agents a fast path...on a deployed Pi" — its own
  docstring), structurally identical to `declare_geometry.py`, `control_token.py`,
  `output_topology_reset.py` in this tile — all of which have **zero in-repo callers by
  design** and are still very much alive via their shipped binary. An orphan sweep that treats
  "no in-repo caller" as orphan-evidence without excluding `pyproject.toml [project.scripts]`
  entries will false-positive on most of this tile's operator doors. The real orphan signal is
  "registered in pyproject but the real running path bypasses it" (the `jasper-web` case
  above), not "nothing in-repo calls it."
- `jasper/wake_legs.py`'s `REGISTRY` (repo root, not this tile) is the documented SSOT for
  on/off/dtln leg tokens; both `wake_score.py` (this tile) and `scripts/_extract_wake_corpus.py`
  (scripts/ tile) re-hardcode the same tuple instead of deriving from it — one fix, two sites.
- `jasper/cli/doctor/audio_runtime_fanin.py` etc. (excluded doctor package, tested together
  with `audio_config.py` in `tests/test_renderer_ring_lanes.py`) shares the fan-in/outputd
  env-file domain with `audio_config.py` here — worth the doctor-tile agent confirming the
  split is read-vs-write and not overlapping logic.
- `jasper/cli/round_views/{cloud_binding,delay,distortion,frequency,grades,inventory,repeat,
  seats,sweeps,__init__}.py` are the sibling tile's files; the 4 I read in this tile
  (`_common.py`, `close_reference.py`, `classify_features.py`, `forward_model.py`) are
