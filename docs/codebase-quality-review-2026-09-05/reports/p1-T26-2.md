# Tile T26-scripts-2 — laptop operator tools (46 files, 13,791 LOC)

## A. Mandate & verdict

**Mandate:** laptop-side operator tooling for a solo-owner Pi speaker: deploy/onboard the
Pi (non-negotiable tier), pull logs/diagnostics off it, and drive several standalone
measurement/training CLIs (wake-word corpus quality, crossover/active-speaker rounds,
multiroom sync, AEC probes) that are deliberately *not* shipped product code.

**Verdict: several coherent sub-systems sharing one directory by convention, not one
system.** Six legible clusters: (1) deploy/identity (`deploy-to-pi.sh`, `onboard.sh`,
`rename-speaker.sh`, `_lib.sh`) — non-negotiable tier, generally excellent; (2)
log/diagnostic pull (`fetch-pi-logs.sh`, `pi-bundle.sh`, `tail-pi-logs.sh`,
`xvf-interrogate.sh`, `capture-chip-mic.sh`); (3) wake-word corpus/gate tooling (a
`_foo.py` + `foo.sh` thin-wrapper pair pattern, applied consistently — this is a genuine
strength, see D); (4) active-speaker/crossover measurement (`run-crossover-round.py`,
`bank-crossover-round.sh`, `s0-sync-measure.py`, `multiroom-spike-measure.py`,
`analyze-correction-diagnostic.py`, `aec-probe-*.sh`); (5) CI/test-lane helpers
(`check-rust.sh`, `check-js-syntax.sh`, `check-provenance.py`, `docs-linkcheck.py`,
`_test_lane.sh`, `tense-grep.sh`); (6) misc single-purpose operator scripts. A newcomer
can navigate by filename prefix; the `_leading-underscore` = "library/impl, not the
CLI entry" convention is applied consistently across the wake-pipeline cluster.
`scripts/_lib.sh` is genuinely the one home for PI_HOST/.env.local targeting, ssh-key
plumbing, and the deploy-direction/identity-guard pure logic — most files correctly
source it. The gaps are concrete and listed below, not systemic.

## C. Top findings (ranked)

1. **Blocker** | `scripts/deploy-to-pi.sh:590-592,602-675,677-687` | `SKIP_INSTALL=1`
   silently skips the identity guard (TOFU peer_id), the deploy-direction/downgrade
   guard, the sudo preflight, the speaker-hostname resolution, and the USB-gadget
   advisory — then `rsync -az --delete` still runs unconditionally. | Evidence: the
   entire block from `resolve_speaker_hostname` through `preflight_deploy_direction`
   sits inside `if [[ "${SKIP_INSTALL:-}" != "1" ]]`; nothing before the rsync
   is gated any other way, and unlike the interactive-sudo skip (which prints
   "speaker identity: skipped (...)"), this path prints **no notice at all**. AGENTS.md
   non-negotiable #4 names exactly two deliberate overrides
   (`JTS_ACCEPT_NEW_IDENTITY=1`, `JASPER_DEPLOY_ALLOW_DOWNGRADE=1`); `SKIP_INSTALL`
   is documented only as "rsync-only," not as a guard bypass. Verified no test exists
   for this path (`grep SKIP_INSTALL tests/*.py` → nothing) despite
   `test_deploy_manifest_gate.py`/`test_deploy_wiring_guards.py` pinning the rest of
   deploy-to-pi.sh's guards. | Fix: run the identity/direction guards and hostname
   resolution unconditionally before rsync; gate only "run install.sh" on
   `SKIP_INSTALL`, not "verify this is the right, non-downgrading Pi."

2. **Blocker (cross-tile, verified from here)** | `jasper/secret_redaction.py:24-30`
   | `_KEY_VALUE_RE`'s `\b(api[_-]?key|...|psk|token)` requires a word boundary
   immediately before the key name, but `JASPER_WIFI_PSK` and
   `JASPER_SPOTIFY_API_KEY` have an underscore (a word character) right before
   `PSK`/`API_KEY`, so `\b` never matches there. | Evidence (executed directly):
   `redact_secrets("JASPER_WIFI_PSK=supersecretpassword JASPER_SPOTIFY_API_KEY=abcdef123456")`
   returns the string **unredacted**. By contrast this tile's own

   used by `fetch-pi-logs.sh`, `pi-bundle.sh`, `bank-crossover-round.sh`) matches a
   *suffix*, not a bounded word, and correctly redacts both — verified with the same
   input. This is the exact gap the task brief named, now confirmed with a runnable
   repro; not in this tile's file list, but load-bearing for secrets non-negotiable
   #3 and directly consumed by three of this tile's log-pulling scripts. | Fix: change
   `_KEY_VALUE_RE`'s anchor to match a name *suffix* (mirroring
   `_diagnostic_redaction.sh`'s regex) instead of `\b`.
