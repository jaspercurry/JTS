# T15 — bass_extension / attribution / route_latency

44 files, 14,273 LOC nominal (14,173 counted by AST walk).

## A. Mandate

Three unrelated systems sharing a tile only by directory proximity:

- **`jasper/bass_extension/`** — a measured, volume-scheduled low-frequency
  alignment feature. **Deliberately parked** by owner ruling
  ([ADR-0018](../../adr/0018-bass-extension-stays-parked.md)): commissioning
  math, adapters, and a bench/measurement toolkit are built; the runtime
  scheduler and the apply/bypass/recovery transaction have zero production
  callers, by design, enforced by an AST-walking test.
- **`jasper/attribution/`** — a small, layered, high-quality "which physics
  owns this response feature" evidence library for one shipped diagnostics
  feature (crossover-v2 commissioning). Not parked, not orphaned, no ADR
  needed — it just quietly earns its keep.
- **`jasper/route_latency/`** — a click/capture route-latency measurement
  harness's supporting modules, consumed by exactly one CLI
  (`jasper-route-latency-harness`) and one laptop script
  (`scripts/jasper-pipe-probe`), **except** `status_socket.py`, which is
  unrelated in mandate — it is the shared `STATUS\n`-socket reader eight
  daemons/CLIs import — and is misfiled here by proximity, not by contract.

Verdict: **not one system**, three defensible-but-distinct ones, one of which
(`status_socket.py`) doesn't belong with its two siblings at all.

## D. If I could do one thing to this tile

Move `route_latency/status_socket.py` out to a top-level shared module — it is
load-bearing infrastructure for 8+ live daemons/CLIs wrongly nested inside a
niche measurement-harness package, and its misplacement is exactly the kind of
"mandate says one thing, import graph says another" boundary rot AGENTS.md
asks agents to fix on sight.
