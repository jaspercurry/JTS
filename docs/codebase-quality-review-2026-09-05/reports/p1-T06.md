# T06 — output-hardware tile (18 files, 15,810 LOC) @ 2d571e6b8

## A. Mandate and verdict

**Claimed mandate:** turn attached audio hardware into one declarative registry → classifier
→ reconciler → doctor/state/wizard chain (ADR-0235).

**Verdict: this is four systems, not one.** Only 7 files (`audio_hardware/*`,
`output_hardware.py`, `output_topology*.py`, `audio_runtime_plan.py`, `audio_runtime_overrides.py`)
serve the output-hardware mandate, and those 7 are genuinely coherent — the registry→classifier→
plan→transport chain reads cleanly end to end. The other 11 landed here by filename prefix:
an input/AEC status classifier (`audio_profile_state`, `audio_input_view`), a voice TTS/mic I/O
layer (`audio_io`), a validation-artifact store + CLI (`audio_validation`), a measurement
coordinator (`measurement_window`), a fan-in route comparator (`audio_validation_route`), an
ALSA-converter preference (`audio_quality`), and product tiering (`install_profile`). A newcomer
reading `jasper/audio_*.py` cannot tell which of them is about output hardware.

**Distance from the ADR-0235 target:** 1 of 13 PRs landed (PR 9, #4091), 2 in flight
(#4117 = PR 2, #4111 = PR 11), **10 remaining**. Every gap I could check on the output side —
G2 (`usb-c to 3.5mm` in `dac.py:414,769` + `jasper-apple-dongle.sh:10` +
`jasper-audio-hardware-reconcile:889`), G3 (nine `sed` extractions + a second `python -c
json.load` spawn), G4 (events on stdout), G5 (`reconcile.degraded` has no reader), G7 (three god
files) — still stands verbatim at HEAD. And the survey **missed two decorative fields and one
duplicated constant** (findings 1–2 below), so #4117 does not finish R1.

**Single-writer `/var/lib/jasper/*.env` — one real violation, one convention gap:**
- `audio_quality.env`: **two writers.** `audio_quality.py:170-176` (web, writes a header naming itself)
  and `deploy/install.sh:1326-1330` (seeds if absent, writes **no header**). Create-only, so no clobber,
  but the seeded file names no writer.
- `i2s_hat.env`: single writer (`usb_port_role.py:390-409`, called only from `web/sound_setup.py:359`),
  but `write_i2s_hat_intent` emits **no header comment naming the writer** — the convention AGENTS.md
  states for this directory.
- `outputd.env`: the disclosed dual-writer (ADR-0235 G8/R7) is *outside* this tile
  (`jasper-audio-hardware-reconcile` + `fanin/coupling_reconcile.py`); `coupling_reconcile.py:26-29`
  does declare its key ownership in the header, so the convention holds on that side.
- `audio_runtime_overrides.json`: `set_runtime_override:227-238` is an unlocked read-modify-write.
  One CLI writer, lab artifact — Nit, not worth a lock.

**Hotplug (device vanishes and returns):** recovery **is automatic**; observability is **thin**.
`deploy/udev/99-jasper-audio-hardware-reconcile.rules:14` fires the reconciler on every
`controlC*` add/remove/change, with `jasper-output-hardware-hotplug` (line 16/17) as the belt for
USB-remove paths that do not activate the vanishing sound node. On return, the reconciler re-classifies
and un-parks with no operator step; `apply_saved_topology_policy` (`output_hardware.py:1103`) explicitly
documents "reconnecting the child re-runs the reconciler through the existing udev chain and un-parks".
`resolve_usb_port_role` deliberately does not flip an OTG port on transient DAC loss (`:424-433`).
What is missing:
1. **No event marks the transition** (F9) — the classifier is silent, so "DAC vanished at 03:14" is
   inferable only from the reconciler's bash `sed` diff.
2. `probe_aplay_listing` can hang unbounded on exactly the vanished-device path (F4).
3. `reconcile.degraded` (`reconcile:58,68,1855`) is **write-only** — read only by
   `write_reconcile_stamp:164`, no doctor check, no `/state` field. A box that flaps into permanent
   probe-unavailable and stops writing DAC format / latency floor is invisible (ADR-0235 G5, PR 7,
   not yet written).
`/state` does carry the record (`control/state_aggregate.py:952-955,1232`) — one reader per fact
holds, as ADR-0235 says — but it is a level, not an edge.
