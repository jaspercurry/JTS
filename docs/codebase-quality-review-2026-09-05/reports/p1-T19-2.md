## A. Mandate and verdict

**Mandate:** everything the fan-in mixer needs that is not the sum loop itself — turn a
host-clocked USB lane into DAC-paced audio (`lane_resampler`), mix ducked assistant/cue audio
into the program (`tts`, `playout`), drain the gadget capture (`mixer/direct_capture`), steer the
host's pitch ctl (`host_clock`), and publish it all (`state`, `xrun_log`, `json`).

**Verdict: one coherent system, correctly layered, with clean internal boundaries** — no import
cycles, no private-name reaching, `playout` reached only by `tts`, `lane_resampler` only by
`mixer`/`state`. The tangle is not *inside* the tile; it is **across the daemon boundary**:
`state.rs`, `json.rs`, `playout.rs` and `tts.rs`'s socket half are each a near-twin of a
`jasper-outputd` file, and the twins have started to drift in ways that are now provable
(§C1, §C2, §C3). The second problem is **weight**: 32% of production lines are comment, much of it
history and issue numbers AGENTS.md forbids outright.

**Requested status checks:**
- **host_compliance/prime machinery — DELETED at HEAD.** No `host_compliance.rs`, no
  `HostComplianceState`, no `service_host_compliance` anywhere in `rust/`. The only surviving
  "prime" is `lane_resampler`'s bounded ring prefill, an unrelated and load-bearing concept. The
  2026-08-25 audit's recommendation was executed. `docs/DEEP-AUDIT-2026-08-25.md:101` still lists
  it as pending — stale doc, another tile's problem.
- **Panic-audit gate (#4093):** clean. Nine panic-capable sites outside `#[cfg(test)]` across the
  tile, all nine carry `// PANIC-AUDITED:`; zero bare `.unwrap()`/`panic!`/`unreachable!`.
- **Gain ceilings (non-negotiable 1):** the duck path cannot boost —
  `config.rs:1048,1060` fail-loud on `tts_program_duck_db > 0` / `tts_cue_duck_db > 0`, and
  `TtsMixer` only ever multiplies the program lane by those. One asymmetry, see §C8.
- **env parsing:** all of it lives in `config.rs` (sibling's tile). Nothing in these 10 files
  reads env except `std::env::temp_dir()` in test helpers.

## E. Cross-tile pointers

- **`rust/` has no `[workspace]` — 8 crates, 8 `Cargo.lock`s.** No version drift *today*
  (alsa 0.12.1, serde_json 1.0.151, libc 0.2.189 agree), but the repo pays for keeping them in
  agreement: three bespoke pytests (`tests/test_build_and_ci_contracts.py:158,194,211`) plus a
  dependabot-atomicity contract exist solely to stop the lockfiles diverging, and
  `deploy/lib/install/rust-daemons.sh:150-198` hand-stages five shared crates with `if [[ -d ]]`
  guards and `chown -R` per crate into **two** separate `/var/cache/jasper-{fanin,outputd}-build`
  trees, so serde_json/libc/log/alsa/anyhow compile twice on every Pi build.
  **Cleanest fix:** one `rust/Cargo.toml` `[workspace]` + `[workspace.dependencies]`, one lockfile,
  one staged tree, `cargo build --release -p jasper-fanin -p jasper-outputd`; delete the three
  version-agreement tests and ~50 lines of the install script. **One real counter-argument:** the
  Zero-class low-RAM path (`run_contained_build`, `rust_cargo_build_env`) currently scopes memory
  per binary; a workspace build must keep `-p` separation or `CARGO_BUILD_JOBS=1` to hold peak RAM.
- `jasper-fanin/src/config.rs:1192-1280` (sibling's tile) reimplements six env parsers
  (`env_str`, feature-token, fallback-key, positive-dimension…) beside its `use jasper_env::{env_f32,
  env_parse, env_str}` import — the shared crate is imported *and* shadowed.
- `jasper-fanin/src/config.rs:1126-1150` reads six `JASPER_OUTPUTD_ASSISTANT_*` env vars to configure
  **fan-in**. A daemon owning config under another daemon's prefix.
- `tests/test_fanin_coupling_auto.py:933` asserts on Rust **source text**
  (`"pub const DEFAULT_CUSHION_DECAY_FLOOR_FRAMES: u32 = 576;" in text`) — the exact thing AGENTS.md
  forbids. `jasper/route_latency/warm_check.py:24` is a third home for the same 576.
- `jasper-fanin/src/state.rs` tests use ~50 raw-substring assertions on the STATUS JSON
  (`j.contains(r#""slots":8"#)`) despite `serde_json` being a dependency; brittle to whitespace and
  key ordering.
- `docs/DEEP-AUDIT-2026-08-25.md:101,179` still lists the host_compliance/prime deletion as
  outstanding; it landed. Stale doc.
- `jasper-outputd/src/state.rs:1948-1962` — the blind-sleep accept loop named in §D.
