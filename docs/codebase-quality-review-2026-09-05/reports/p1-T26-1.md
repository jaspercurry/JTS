# T26-scripts-1 — laptop operator tools (half A: 46 files, 13,792 LOC)

## A. Tile mandate

**Mandate:** laptop-side operator tooling for JTS — SSH-driven capture/probe
harnesses for AEC/wake/multiroom hardware work, offline wake-corpus/training
data-prep, CI classification/parity checks, and small speaker-config utilities.
Not the deploy/test-lane path itself (owned by sibling tile T26-scripts-2:
`deploy-to-pi.sh`, `onboard.sh`, `test-fast`, `test-merge`, `_test_lane.sh`,
`fetch-pi-logs.sh` — read for cross-reference per Extra Focus, findings below).

**Verdict:** several coherent, well-bounded subsystems sharing one convention
layer (`_lib.sh` + `_pi_target.py`), not one tangled system. Four real families:
(1) wake-corpus/training data-prep pipeline (11 files, one clean pipeline: export
→ audit → build-features → prepare-workdir → phase0 runner, each with matching
thin `.sh` wrapper), (2) hardware AEC/sync probes (aec-probe-*, s0-sync-bench,
multiroom-spike — throwaway-labeled benches, correctly so), (3) CI/release
tooling (ci-classify.py, docs-impact.py, check-*.mjs, _first_party_arm64_release.py),
(4) one-off speaker-config utilities (switch-voice-provider, claim-librespot,
refresh-mta-stations, airplay-reset, jasper-trace). Code quality is unusually
high and self-aware (extensive "why", safety framing, fail-closed defaults)
across the whole tile — this is not where the codebase's problems concentrate.
