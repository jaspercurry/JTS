# Audit: `jasper/voice_daemon.py` (5,476 lines)

**Measured shape.** `WakeLoop` spans `jasper/voice_daemon.py:888-5415` (4,528 lines), **96 methods** (not ~114), and **102 `self._*` fields** assigned in `__init__` (`jasper/voice_daemon.py:906-1273`, 368 lines). Prose (comments + docstrings) is 1,589 lines against 3,550 code lines and 425 blank — a **0.45 prose:code ratio**. It is a god class, but an unusually *legible* one: the coupling is real, not accidental, and four concerns are already almost free-standing.

**The true core.** Strip the telemetry inlay (~130 lines from `_handle_wake_frame`), the research branches (~60), the PTT branches (~90), the server-VAD negotiation (~55) and `session_status` (89), and the minimal wake→turn→end machine is **≈1,170 lines including prose, ≈800 lines of code**: score a frame → OR-gate + fuser verify → buffer + arbitrate → open turn (duck, loudness, acquire, pre-roll) → dispatch session frames through one endpointer → end (cancel bg tasks, end_input, release, chirp, undock). That is a defensible size for what it does; the file is 4.7× that.

## 2. Extraction plan

Seven modules. Order matters — 1-4 are near-free, 5-6 are moderate, 7 is the only one that touches the hot path.

**1. `jasper/voice/measurement_gate.py` (~544 lines, near-zero coupling).** Move all 16 measurement methods plus constants `jasper/voice_daemon.py:523-580` and the `_measurement_safety_sleep` / `_measurement_monotonic` seams. Owns `_measurement_active/_safety_task/_transition_lock/_lease_generation` in a `MeasurementGate` class. Contract the core calls: `gate.is_active()` (the per-frame read at 2447, 2536, 2557, 3928, 4634), and `gate.pause()/resume()`; the gate takes `output_gate`, `content_activity`, `volume_coordinator`, `tts` and a `session_active: Callable[[], bool]` for the BUSY check. `WakeLoop.measurement_pause*/measurement_resume` become 3-line delegations for the UDS handler at `jasper/voice/daemon_main.py:607`. **Do this first** — it is the largest, cleanest win in the file.

**2. `jasper/voice/peering_client.py` (~94 lines, lowest coupling).** Move `_peering_send`, `_peer_arbitrate`, `_notify_peering_session_started/ended` and `_peering_current_epoch`. Contract: `arbitrate(score, snr_db, rms_dbfs, can_serve) -> "WIN"|"LOSE"`, `session_started()`, `session_ended(reason)`. The only `WakeLoop` state it reads is `self._turn is not None` at 4032, which becomes a parameter.

**3. `jasper/voice/research_announcer.py` (~371 lines, high coupling — extract anyway).** Move the 12 research methods, `_research_confirmation_instruction` (138-148) and constants 425-435, plus the 13 `_research_window_*` fields. This one **needs a callback interface**, not a plain move: the announcer must be able to `begin_turn(pre_roll=False, text_context=…)`, `end_turn(reason)`, `play_dynamic_text`, `play_cue`, and read `state/mic_muted/measurement_active/spend_cap/connection_paused`. Define a small `TurnHost` protocol the `WakeLoop` satisfies. Five inlays stay in the core as one-line hooks: `run:2497`, `_wake_leg_loop:2586`, `_handle_wake_frame:3455`, `_end_turn_inner:5391`, `session_status:4805`. Net: the core shrinks by ~360, gains ~25.

**4. `jasper/voice/wake_telemetry.py` (~256 lines).** Move the 8 funnel methods, `_LEG_DB` (783-812), `_frame_rms_dbfs`/`_ring_noise_floor_dbfs` (657-712) and — the real prize — the inlaid `_handle_wake_frame:3484-3630` block into a `WakeFunnel.on_fire(leg, score, fired_set, legs, condition, …)` call. That single move takes `_handle_wake_frame` from 285 lines to ~150 and puts every SQLite touch behind one seam (see finding H3). Owns `_wake_event_store`, `_current_event_id`, the capture rings.

**5. `jasper/voice/push_to_talk.py` (~366 lines).** Move `_ptt_input_cap_sec`, `_handle_manual_session_frame`, `_push_to_talk_keepalive_ticks`, `_manual_mic_loop`, `_endpointer_label`, `_corpus_endpointer_label`, `_ManualMicRuntime` (766-782) and constants 321-361. `manual_session_start`/`manual_session_end` stay on `WakeLoop` (they are turn-lifecycle entry points on the control socket) but shed the ~60 lines of PTT-specific guard logic into a `ManualMicSet` helper. Moderate difficulty: `_manual_endpoint_this_turn` is read in five clusters.

**6. `jasper/voice/assistant_output.py` (~594 lines).** Move the 14 cue/episode methods, `FanInDucker` (204-297), `_synthetic_audio_profile` (118-136) and the earcon pre-bake block `__init__:1113-1162` into an `AssistantOutput` facade over `_output_gate`, `_ducker`, `_cues` and `_tts`. This is the second-largest win and also the right home for `FanInDucker`, which today sits in `voice_daemon.py` while its sibling `Ducker`/`CueDuck` live in `jasper/camilla.py:1265` — one concern, two modules (rubric: converge).

**7. `jasper/voice/endpointer.py` (~250 lines) — flag: needs a wide refactor, do last or not at all.** The three endpointing branches in `_handle_session_frame:4364-4531` plus `_resolve_barge_in_for_turn`/`_handle_playback_frame` are a natural `Endpointer` strategy (`ServerVadEndpointer`, `SileroEndpointer`, `ManualEndpointer`), but they mutate 11 shared per-turn fields (`_user_speech_seen _silence_started_at _input_ended _speech_run_* _max_silero_* _silero_*_armed_at_ms`) that `_begin_turn_inner:4916-4924` resets and `_end_turn_inner:5209-5215` reads for telemetry. Extracting cleanly means moving that whole per-turn state bag into a `TurnState` object first. **This is the one extraction that would touch the hot path and the non-negotiable no-silent-deafness surface; it should not be bundled with any of 1-6.**

After 1-6 the file is roughly `WakeLoop` core + `ContentActivityTracker` + `_LegRuntime` + `_configured_wake_legs` ≈ **1,400-1,600 lines**.

**`for_tests` (`jasper/voice_daemon.py:1276-1460`, 185 lines).**
**Not justified.** It ships nine stub classes (`_TestMic`, `_TestDetector`, `_TestTts`, `_TestConnection`, `_TestDucker`, `_TestContentActivity`, `_TestUsageStore`, `_TestSpendCap`, `_TestVolumeCoordinator`, `_TestVad`) and a fake `SimpleNamespace` config into the production module that runs on the Pi, plus a `setattr`-based `**overrides` back door that lets tests reach past `__init__`. It has **275 references across 18 test files** and **zero production callers** (verified: no `for_tests` reference in `jasper/`, `scripts/`, or `deploy/` outside its own definition comment at line 829).

Replacement: move it verbatim to `tests/_wake_loop.py` (or a `wake_loop` fixture in `tests/conftest.py`, which currently has none) and import it from there. The class already builds through the real `cls(...)` constructor, so nothing behavioural changes — this is a file move plus 18 import edits, and it deletes 185 lines plus the `_UNSET` sentinel (`jasper/voice_daemon.py:826-829`) from production. The two `for_tests`-adjacent knobs (`vad=`, `legs=`) stay real constructor parameters, which they already are. Same argument retires `_synthetic_audio_profile` (see D2).

## 5. Hot-path correctness and latency

### Sequence A: score crosses threshold → first mic frame reaches the provider

Inside `_handle_wake_frame` (all synchronous until step 7):

1. `:3400` acquire `_wake_fire_lock` (uncontended fast path, no yield); recompute `fired_set` over all legs.
2. `:3435` `detector.reset()` × N legs.
3. `:3445` `_fuser.verify()` — the precision gate.
4. `:3482` **`import time as _time`** then `monotonic()`.
5. `:3484-3510` build per-leg score dict + `log_event`.
6. `:3527` `_frame_rms_dbfs(frame)` — one numpy pass.
7. `:3532-3630` **the telemetry block, and this is where the latency is:**
 - `:3572-3580` nine `os.environ.get` calls. Cheap (dict reads) — *not* a real cost, despite looking like one.
 - `:3600` **`_ring_noise_floor_dbfs(self._capture_ring_on)`** — a numpy RMS over up to **100 frames** (`CAPTURE_RING_FRAMES` = `(4+2)·16000/1280 + 25`). At the `_frame_rms_dbfs` docstring's own "≤80 µs per frame on Pi 5" that is ~8 ms; on the supported Pi Zero 2 W, materially more. **And it is the second full scan within one second** — `_maybe_refresh_condition:3353` already ran the identical `classify_condition(_ring_noise_floor_dbfs(...))` at most `CONDITION_REFRESH_SEC` (1.0 s) earlier, and the `firing_threshold` at `:3395` was already computed from that cached value. The recompute changes only the recorded `condition_class` and the *next* frame's threshold.
 - `:3604` **`await store.begin_event(...)`** — a SQLite INSERT executed on the event loop (`jasper/wake_events.py:423` uses `self._conn.execute` under an asyncio lock; only `attach_audio`'s WAV writes get `asyncio.to_thread`). The store is opened unconditionally at `jasper/voice/daemon_main.py:916`, so this is on every production wake. On a busy SD card this stalls the whole loop, including the mic drain.
8. `:3635` spawn `_arbitrate_acquire_drain`; return to the mic loop.

Then in `_arbitrate_acquire_drain`:

9. `:3812` `_wake_late_cancelled` (sync).
10. `:3817` `await _peer_arbitrate(...)` — returns instantly when peering is off (`_peering_send:3955` short-circuits before any I/O); otherwise a UDS round trip bounded at 0.5 s.
11. `:3846` `await self._begin_turn(listening_feedback=True)`:
 - `:4857` `_begin_turn_output_episode()`
 - `:4858` **`await _prepare_assistant_loudness_context()`** → up to one `effective_volume_context()` IPC to the volume coordinator plus one `tts.prepare_assistant_context()` IPC. **The listening chirp is queued behind this**, at `:4862`.
 - `:4862` chirp spawned (fire-and-forget) — **first audible feedback**.
 - `_begin_turn_inner`: `:4897` another `import time as _time`; `:4930` `_resolve_barge_in_for_turn()` (one `os.stat` via `read_barge_in_enabled`); `:4934` **`await _content_activity.refresh_now()` — a CamillaDSP websocket round-trip** (`jasper/camilla.py:513`) for a value the background poller already refreshes every 1.0 s (`CONTENT_ACTIVITY_POLL_SEC`); `:4935` **`await _prepare_assistant_loudness_context()` a second time**, duplicating `:4858` in full; `:4936` `tts.pause_content_meter()` IPC; `:4950` **`_usage_store.open_session()` — a synchronous SQLite INSERT on the loop** (`jasper/usage.py:540`, documented as hot-path and fail-soft); `:4953` `await acquire_turn()` (network; up to ~3 s on a context reset); optional `set_turn_detection` network round-trip at `:4995`; `:5029` the timing `logger.info`.
 - `:5044` pre-roll loop, up to 7 × `await self._turn.send_audio(...)` ← **first mic frame reaches the provider here**.
12. `:3862` `await _telemetry_stage("turn_opened")` — SQLite UPDATE.
13. `:3865` `await _notify_peering_session_started()` — UDS, up to 0.5 s.
14. `:3868` `await _drain_acquire_audio()` ← **everything the user said during the acquire window reaches the provider only now**, behind steps 12-13.

**The two orderings to fix:** the listening chirp sits behind a full loudness-context IPC (`:4858` before `:4862`); and the acquire buffer — the user's actual question on any slow-acquire turn — sits behind a SQLite UPDATE and a peering UDS round-trip (`:3862`, `:3865` before `:3868`). Both `:3862` and `:3865` are pure notifications with no bearing on audio and belong after the drain, or in a spawned task.

### Sequence B: end-of-utterance → first TTS byte written

Clean. `_handle_session_frame:4522` detects `now - _silence_started_at >= END_OF_UTTERANCE_SILENCE_SEC` → `_end_session_input("end-of-utterance")` (`:4178`) sets `_input_ended = True` and issues exactly one `await self._turn.end_input()`. `_play_responses` is already running as a `_bg_task` from `:5058`, so the first TTS byte is written the moment the provider streams it. **One await, no I/O, no allocation.** The only nit: the frame that triggered EOU is dropped rather than forwarded (`:4526` returns before `_send_session_audio`).

The *turn-end* tail is the opposite. Between the last provider chunk and the "done listening" chirp at `:5380`, `_end_turn_inner` awaits, in order: `_telemetry_stage` (SQLite, `:5195`), `_telemetry_outcome` (SQLite, `:5202`), `update_session_vad` (SQLite, `:5213`), `_notify_peering_session_ended` (UDS ≤0.5 s, `:5222`), bg-task cancel+join, `tts.end_segment()`, **`asyncio.wait_for(self._turn.end_input(), timeout=2.0)`** (`:5273`), `turn.release()`, `_usage_store.close_session()` (sync SQLite), and `_record_conversation_turn()` (`:5286`) — which does an env-file read (`jasper/conversation_history.py:317`), a SQLite insert and a retention prune, all synchronously on the loop. Worst case that is **~2.5 s plus four SQLite writes before the user hears the turn ended.**

### Per-frame costs

`_handle_session_frame` runs at 12.5 Hz per turn: `any(t.done() for t in self._bg_tasks)` allocates a generator every frame (`:4366`); `asyncio.get_event_loop().time()` is called on every frame path (`:4395`, `:4454`, `:4123`, `:4343`) and every wake frame (`:3376`) — 17 sites file-wide, where `asyncio.get_running_loop()` is the ≥3.11 form; and the server-VAD branch re-resolves `getattr(self._turn, "server_speech_started")` and `"server_speech_detected"` per frame (`:4410`, `:4436`) instead of once per turn. There is also `assert self._turn is not None` at `:4371` on the per-frame path — asserts are live unless `-O`, and this one is load-bearing enough that it should be an explicit guard or nothing.

During a research confirmation window, `run:2497-2500` dispatches every primary frame to **both** `_handle_wake_frame` and `_handle_session_frame` — double detector + VAD work. Narrow (seconds), but worth knowing.

## 6. Resilience and observability

**What works well.** Failure surfaces are three-layered and mostly consistent: a cue (the household's answer), an `event=` log line, and `/state.voice` via `session_status:4724-4812`. The `wake_events` corpus is a genuine per-turn latency trace with **millisecond-resolution stage timestamps** (`jasper/wake_events.py:93-103` maps nine stages to `ts_*` columns; `_now_iso:265` uses `timespec="milliseconds"`), covering `late_cancel → peer_lost → gate_blocked → turn_opened → speech_detected → response_started → tool_called → tool_completed → turn_complete` plus a validated terminal outcome. `_begin_turn_inner:5029` additionally logs a segmented `wake→activity_start` breakdown (`sched_lag / state / loudness_prepare / duck / acquire`), which is exactly the instrument needed to localise the latency in §5.

**Deafness paths — audited.** Every wake-path refusal cues: spend cap → `spend_cap_reached` (`:3838`), paused connection → `_connection.wake_cue()` (`:3856`), unexpected error → `internal_error` (`:3900`), no room mic → `NO_ROOM_MIC_CUE_SLUG` (`:4620`). The silent ones — `_wake_late_cancelled` (mute/measurement) at `:3812`/`:3826`, and `peer_lost` at `:3820` — are correctly silent: the household just asked for that silence, or another speaker is answering. `_play_cue:2205-2222` even latches a one-shot WARN when there is no cue manager, so a permanently mute daemon is diagnosable.

**Three real gaps.**

1. **`manual_session_start` returns `"CAP"` (`:4645`) with no cue, no `session.manual_refused` log, and nothing on the control side.** The wake path plays `spend_cap_reached` for the identical condition (`:3838`). `jasper/control/handlers/voice.py:95` maps it to HTTP 503 and `jasper/control/server.py:1649` only fires `refusal_event` on an unreachable daemon — so a button press at the spend cap produces **total silence and an empty journal**. Every sibling refusal in that same method logs (`:4632`, `:4638`, `:4654`).
2. **`manual_session_start`'s error path (`:4695-4701`) cues only when the connection is paused.** The wake path's equivalent (`:3897-3900`) has the `else: _play_cue(INTERNAL_ERROR_CUE_SLUG)`. On the button path, `_begin_turn` has already fired the "now listening" chirp (`:4862`) — so the user gets a chirp, then nothing at all. `INTERNAL_ERROR_CUE_SLUG` has exactly one call site in the whole repo (`:3900`); the second one is missing.
3. **A fuser suppression (`:3446-3454`) produces one log line and nothing else.** No cue (defensible — it means "we don't think you spoke the wake word"), but also **no `wake_events` row**: `store.begin_event` is at `:3604`, past the `return` at `:3454`. So the precision stage's false-negative rate is unmeasurable from the corpus that exists to measure exactly that, and `session_status` carries no suppression counter either.

**Lesser gaps.** Push-to-talk turns get no corpus row at all — `_corpus_endpointer_label:4219-4221` says so outright ("`push_to_talk` is only observable on the `/state` side today"), so the entire PTT surface is invisible to offline review. `jasper/voice/trace.py` — a full per-turn structured trace — is **not wired into `voice_daemon.py` at all**; its only production emitter is `jasper/voice/openai_session.py:1751`, and it no-ops unless a `voice_eval` harness set an active trace. There is no funnel stage between `turn_opened` and `speech_detected`, so the acquire-drain window measured in §5 is not instrumented. `manual_session_start` returning `"BUSY"` (`:4623`) also logs nothing.

## 7. What is genuinely good — do not touch

- **The constant block `:312-497`.** Every threshold carries its derivation, its corpus, the failure mode it rejects, and the sweep that picked it (`SPEECH_RUN_PEAK_MIN` at `:479-489` names `scripts/probe-wake-gate.py`; `SUSTAINED_SPEECH_TO_ARM_SEC` at `:460-476` explains why it is *not* OVOS's 0.3 s). This is the file's best asset and the model for what the rest of the prose should be.
- **The OR-gate + refractory critical section (`:3400-3427`).** The lock covers only the race window, refractory is set inside it, and the rest of the fire path runs unlocked. Correct and minimal.
- **The recall/precision split (`:3438-3454`).** Threshold-crossing proposes, `_fuser.verify` corroborates, and it **fails open** with only the short refractory held. The right default for a wake word.
- **The `_end_turn` re-entrancy guard (`:5152-5174`).** A dedicated `_ending` flag rather than an early `_state` flip, precisely so the teardown chirp cannot be garbled by a supervisor cue or timer. Subtle and correct, and the comment (item 11 in §4, long as it is) earns its length here.
- **The measurement-pause ordering (`:2643-2733`).** Admission closes, then the event is set, then the safety backstop is armed, all before the drain — so no episode can start mid-drain and a crash mid-drain still auto-clears. The aggregate-deadline arithmetic (`:547-580`) is pinned by tests against the coordinator's own timeout.
- **`_output_admission_refusal` (`:2968-2977`) wired into `tts.set_emission_admission` (`:1012`).** One admission authority asked twice — once when an episode wants to start, once when its bytes want to leave. That is the right shape for a gate that must hold across a topology with worker-thread socket writes.
- **`_endpointer_label` / `_corpus_endpointer_label` (`:4194-4225`).** One vocabulary, two readers, defined once. Exactly the anti-drift discipline the rubric asks for.
- **The `deferred_cancel` / `uncancel()` ownership pattern.** Individually correct in all four places; the finding against it (D9) is only that it should exist once.
