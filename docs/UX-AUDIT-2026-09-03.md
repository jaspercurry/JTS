# JTS web UI — cleanup program (handoff for the orchestrating agent)

This is the working brief for the front-end cleanup of the `jts.local`
management UI. It is a work queue with an execution ledger, not doctrine:
decisions it produces go to `docs/adr/` and `docs/web-ia.md`; delete this file
and its directory when the ledger is done.

Evidence: six read-only agent audits of all 25 sub-pages, run 2026-09-03
against `main` at `c6329be2d`, are in [`ux-audit-2026-09-03/`](ux-audit-2026-09-03/)
(`report-voice`, `-connect`, `-system`, `-sound`, `-measure`, `-crosscut`,
plus the `BRIEF.md` they were given). Every finding there cites `file:line`.
Two disposition studies (`/balance/`+`/sync/`, subwoofer code) and their
ready-to-run deletion prompts sit beside them as `PROMPT-*.md`.

## 0. How the orchestrator works

You are the orchestrating agent (a Fable instance): architect, coordinator,
debugger, and the one with taste. You do not write the code. You:

- **Delegate** every investigation and every implementation to a sub-agent.
  Sonnet for mechanical work (moves, deletions, adopting a primitive that
  already exists, copy with the words supplied, widening a guard). Opus where
  the task decides an order, a name, a seam, a component shape, or touches
  the measurement/commissioning flow. Run independent agents in parallel;
  serialize anything that edits `deploy/assets/app.css`, `jasper/web/nav.py`
  (once it exists), or `deploy/nginx-jasper.conf`.
- **Gate** each PR: the implementer runs `scripts/test-fast`, then `/simplify`,
  then `/code-review` (medium) inside its own session and fixes or wontfixes
  every finding before pushing. You read the diffstat and the review summary
  and triage. Nothing here is on the AGENTS.md non-negotiable list unless a
  PR wanders into volume clamps, DSP math, secrets, or `install.sh`; if one
  does, add `/adversarial-review`.
- **Verify at the surface.** After each area lands: `bash scripts/deploy-to-pi.sh`,
  open the pages on a phone, then the owner eyeballs. Batch the invisible PRs;
  eyeball the visible ones one area at a time.
- **Keep the ledger** in §7 current: tick rows as PRs merge, add rows you
  discover, strike rows that stop making sense. The PR description is the
  record of what changed; this file is the record of what is left.
- **Re-derive at HEAD.** The audits are a month old by the time you read
  them. Before acting on a finding, have the implementer confirm it still
  holds; never trust a line number.
- **Ask the owner** only at the gates marked in §3, or for a decision that
  would be expensive to undo (a URL move, a deletion the studies marked
  "unclear"). Everything else is your call.

Anti-bloat rules (owner's explicit ask, on top of AGENTS.md defaults):
no new docs beyond `docs/web-ia.md` and ADRs for real decisions; no new test
file per page (extend the page's existing `tests/test_web_<page>.py`, delete
tests whose subject moved); no compatibility shims, feature flags, or dual
paths for the migration (deploys are cheap, a broken sub-page is recoverable);
no comments narrating the change; every touched file leaves smaller unless
the feature grew. Guards only where this program found a recurrence (§5).

## 1. Decisions already made by the owner (do not re-ask)

1. **Principles.** The UX-law prompt is applied as lenses, not a checklist.
   The durable artefact is a ≤60-line `docs/web-ia.md` (draft in
   `report-crosscut.md` appendix) plus `.claude/skills/web-ui/SKILL.md`, ~10
   lines, whose only job is to load `web-ia.md` and `design-language.md`
   when a diff touches `jasper/web/`, `deploy/assets/`, or the nginx conf.
   `design-language.md` keeps its craft-layer scope; fix its dangling
   AGENTS.md pointer (line 24) to point at `web-ia.md`.
2. **Landing page.** `deploy/index.html` stays as it is *structurally*:
   typography, hierarchy, spacing, grouping style, hover, hero. Its **copy,
   row labels, row grouping, and section headings may change** to make the
   IA make sense. Known confusions to fix: "Room correction" next to
   "Microphone measurement"; "Voice" next to "Voice assistant"; "Software"
   and "Status" both opening `/system/`; "Speakers" (pairing) under Network
   when it is a Sound concern; "Integrations" reading as unrelated to the
   assistant they serve.
3. **Secondary menus.** Introduce a second level of hierarchy where an area
   has several children: a hub page that looks like the landing page's
   settings groups (iOS Settings is the reference), from which the user
   lands on the leaf. Do not over-nest: a leaf stays a top-level row when it
   has one purpose. Advanced settings belong in secondary pages, not in
   disclosure-stacked cards.
4. **URLs move.** The URL mirrors the menu path. No debt: URL, landing label,
   `<title>`, header title, and back-link target must agree, enforced by
   test. No legacy support: the `/correction/*` alias namespace is deleted,
   moved pages get no redirects **except** paths held by external systems
   (OAuth callbacks under `/spotify/` and `/google/`, anything a Home
   Assistant integration or a registered webhook points at — verify before
   moving those).
5. **Type ladder and craft rules go site-wide.** The 11/12/13/14/16 ladder,
   three-tier text ramp, depth strategy, 44/40 px targets, and motion policy
   apply to every page, with the guards widened accordingly. Done per touched
   page, with the ladder guard extended to each sheet as it comes clean.
6. **Front-end architecture: vanilla, modular, DRY, one source of truth**
   (§4). Refactor pages that do not follow it; do not rewrite pages that
   already do. A staff engineer opening `deploy/assets/` should find one
   way of doing each thing.
7. **Deletions are approved.** Retired active-speaker routes in
   `sound_setup.py`, the legacy `?msg=` redirect shim, dead helpers, dead UI,
   and anything the two disposition studies mark DELETE. **Keep:** the bass
   extension module (ADR-0018; surfaces as a "coming soon" placeholder), the
   room-correction code (coming soon), the measurement visualisation
   (`/sound/measurements/`; find where it fits). **Subwoofer:** a sub that is
   just another DAC channel taking low frequencies is part of the crossover
   channel model and stays; independent, wireless, paired, or role-based
   subwoofer machinery goes (`PROMPT-subwoofer-deletion.md`).
8. **`/balance/` is deleted** (its output is duplicated by the pair page's
   slider and its link was deliberately removed under #1842/#2632);
   **`/sync/` is kept and folded into the pair page** as the only writer of
   the pair timing knob, after its two correctness gaps are fixed. Evidence
   and the ready-to-run work in `PROMPT-balance-sync.md`.
9. **Guards.** Structural guards that pin single ownership are welcome; no
   guard for anything judgement-shaped ("one purpose per screen").

## 4. Front-end architecture standard (what "best practice" means here)

The rule set the implementers build to and the guards enforce. Vanilla only;
Pi-class resource budget; no framework, no build step beyond the install-time
render of static pages.

- **Python page module** = routes + data assembly + rendering. Render
  functions stay under ~80 lines and compose small helpers; conditionals are
  fine in an f-string, loops and business logic are not. Data reaches the
  browser through `json_island`, never by interpolating JS. Every page renders
  through `canonical_page` and `canonical_header`; titles and back links come
  from the nav manifest.
- **HTML**: semantic elements; `hidden` attribute (never `style=display:none`
  or a `.hidden` class); no inline `style=` attributes; one `<form>` per
  submit with a real submit button; `.btn--primary` at most once per section.
- **CSS**: `app.css` owns tokens, reset, fonts, and every primitive used by
  two or more pages; `deploy/assets/<page>/<page>.css` holds only that page's
  components and never re-declares an `app.css` selector; every size on the
  ladder, every colour from the ramp or a `--tone`; class naming follows
  `app.css`'s `block__element--modifier`.
- **JS**: one ES-module entry per page (`deploy/assets/<page>/js/main.js`)
  under ~400 lines, split by concern beyond that; shared behaviour lives in
  `deploy/assets/shared/js/` (`http`, `dom`, `escape`, `dialog`,
  `measurement-audio`, `chrome`, polling) and a page never re-implements one;
  DOM is built with `dom.js` helpers, never `innerHTML` string concatenation;
  server-rendered markup is updated in place, not re-rendered wholesale on a
  poll; every poller uses the shared helper and backs off when hidden; every
  click acknowledges immediately (disable + words), and every failure says
  what happened and what to do next.
- **Submit models**: form → POST → 303 → flash → `canonical_banner` for pages
  that are a form; fetch + JSON + in-place update for live surfaces. One per
  page. A rejected POST re-renders with the user's values, never a bare flash.
- **Copy**: the landing label is the page's name everywhere; name what the
  user controls, never the daemon, unit, env key, or protocol stage; net word
  count goes down in every IA PR.

## 5. Guards to add (each tied to a recurrence in the audits)

1. Landing label = `<title>` = header title = nav-manifest entry, and every
   page's back link targets its manifest parent (recurrence: 7 mismatched
   rows, 3 headers saying "Correction").
2. Every page shell renders `.app-header` (recurrence: `/balance/`, `/sync/`).
3. No page sheet re-declares a selector `app.css` owns; allowlist scoped
   overrides (recurrence: `.btn-row` ×3, `.boot-note` ×2, `.disclosure` ×13,
   badge ×4). Generalises the existing spinner/toggle tests.
4. Type ladder and text ramp checked on every sheet, not only `index.html`
   (recurrence: 97 off-ladder declarations in 13 sheets).
5. No inline `style=` in `jasper/web/*.py` HTML (recurrence: 21 in
   `correction_room_flow.py`, 8 in `google_setup.py`).

Not guards: page purpose, primary-action count, section order, copy
vocabulary. Those are the orchestrator's taste and the owner's eyeball.
