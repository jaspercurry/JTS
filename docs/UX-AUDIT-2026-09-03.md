# JTS web UI — UX / IA audit and cleanup program (2026-09-03)

Point-in-time audit of the 25 management sub-pages under `jts.local`, run by
six parallel read-only agents against `main` at `c6329be2d`, with the owner's
UX-law prompt as the lens. The landing page `deploy/index.html` was explicitly
out of scope (protected reference, design-language.md §2). Per-page evidence
with `file:line` citations lives in the six cluster reports under
[`ux-audit-2026-09-03/`](ux-audit-2026-09-03/); this file is the program.

Delete this file and its directory once the program is done or abandoned —
it is a work queue, not doctrine.

## 1. Should the UX laws become a skill? — Yes, as a 55-line doc plus a loader

The 20-law prompt is good input and bad doctrine. Half of it is already owned
by [`design-language.md`](design-language.md) (touch targets, motion,
copy, errors) or is inapplicable to a one-user appliance (goal-gradient,
Zeigarnik, onboarding funnels). Applied mechanically it would produce the
false positives that doc's §12 filter exists to suppress. What the audit
actually found is that the sub-pages fail on **eight recurring patterns**,
not on twenty laws:

1. A page with no way back, or no link into it (`/balance/`, `/sync/`).
2. A save that says nothing (`/wake/` discards every flash; `/voice/`'s
   slowest action has no busy state).
3. The thing you came for is below prose, diagnostics, or a collapsed
   disclosure (`/voice/`, `/spotify/`, `/sound/setup/`, `/rooms/`).
4. Competing primaries (`/transit/` four save buttons; `/wifi/` two Connects;
   Forget in danger red beside Connect on every device row).
5. Implementation vocabulary as UI copy (bond UUIDs, BlueZ stages, env keys,
   "Correction" as a page title).
6. Typed input destroyed on a rejected submit (`/speaker/`, `/transit/`,
   `/weather/`, `/voice/`).
7. Same widget, N implementations: `.disclosure` ×13 page sheets and none in
   `app.css`; page header ×4; badge ×4; confirm-on-submit ×4; copy-to-clipboard
   ×3; `setInterval` pollers ×12 with 8 never backing off when hidden.
8. Monolith files that stop the cleanup from being safe (`sound-profile/js/main.js`
   7.6k lines, `sound_setup.py` 5.5k, `correction_crossover_v2.py` 7.6k,
   `correction/js/main.js` 3.4k single IIFE).

So the durable artefact is a short IA contract that names those patterns,
not a restatement of the laws. Concretely (the cross-cutting report §5 and its
appendix carry the full draft):

- **`docs/web-ia.md`** (≤ 60 lines): every page is a leaf of the landing page;
  one name in three places (landing label = `<title>` = header title); every
  page renders `canonical_header` with a back target; a single-owner table for
  shared primitives (`_common.py`, `app.css`, `shared/js/*`); the two submit
  models (form→303→flash, or fetch→in-place) and the no-silent-click rule;
  pollers back off on `document.hidden`; a false-positive filter. It also
  becomes the target of the dangling pointer at `design-language.md:24`
  ("Web wizard conventions" in AGENTS.md no longer exists).
- **`.claude/skills/web-ui/SKILL.md`** (~10 lines): when a diff touches
  `jasper/web/`, `deploy/assets/`, or `deploy/nginx-jasper.conf`, read
  `docs/web-ia.md` and `docs/design-language.md` before writing markup. It
  loads the docs; it does not restate them (design-language §13 already
  rejected a second SSOT).
- **Not** an edit to `design-language.md` beyond the link fix: its §1 scopes
  it to the measurement flow and its §13 exclusions stay ratified.
- **Two structural guards**, each tied to a recurrence found here: every page
  shell renders `.app-header`; no page sheet re-declares a selector `app.css`
  owns. Nothing judgement-shaped ("one purpose per screen") becomes a test.

## 3. The program — four phases, ~60 single-concern PRs

Every PR: < 400 changed lines (additions count, deletions do not), one
concern, `scripts/test-fast` before push, `/code-review` medium, deploy and
eyeball on the Pi before the next one in the same page. Ordering inside a
phase is by dependency; phases can overlap once Phase 0's primitives land.
"Tier" is the cheapest model the audit judged able to do it well.

### Phase 4 — owner decisions, not cleanups

- **Type ladder beyond the measurement flow.** 97 off-ladder declarations in
  13 sub-page sheets. Mechanical, but design-language §1 disclaims this scope.
  Decide once; if yes, one Sonnet PR per cluster and widen the ladder guard.
- **`/sound/` namespace.** `/eq/` and `/sound/setup/` are one module behind two
  URLs; `/sound/*` is two daemons and two nav models; `/correction/*` is a
  12-URL alias set for 6 pages that leaks into copy. Consolidating is a URL-
  stability call.
- **Landing-page names.** Sub-page titles will be renamed to match the landing
  row labels (the non-protected side). Three rows carry hardcoded status
  strings ("Synced", "Household routing") that never reflect state — noted,
  not proposed, because `index.html` is protected.

## 4. How to run it with sub-agents

- **Land 0.1 first.** After that every implementer loads `docs/web-ia.md`
  and `design-language.md` through the skill, so the brief stops being
  re-sent per task.
- **One PR per agent session**, spawned from the table row plus the cited
  report section. The prompt template that worked for the audit:
  *read AGENTS.md, web-ia.md, design-language.md; read `<report>#<finding ids>`;
  implement exactly those ids; vanilla HTML/CSS/ES modules only, static assets
  under `deploy/assets/<page>/`, reuse the single-owner table before writing
  anything; leave every touched file smaller unless the feature grew; run
  `scripts/test-fast`; push to the named branch; report the diffstat and the
  one thing to eyeball on the Pi.*
- **Tier as marked.** Sonnet for deletions, moves, adoptions of a primitive
  that already exists, and copy with the words supplied. Opus where the PR
  decides an order, a name, or a seam. Nothing here is non-negotiable tier
  (no clamps, DSP math, secrets handling, or `install.sh`), so the review is
  `/code-review` medium; owner triage per AGENTS.md.
- **Verify at the surface.** Deploy with `bash scripts/deploy-to-pi.sh`,
  open the page on a phone, then merge. Phase 0 and Phase 1 PRs are visually
  near-invisible and can batch; Phase 2 PRs get eyeballed one at a time.
- **Keep the ledger here.** Tick rows in this file as PRs merge; delete the
  file when the table is done or the owner stops.
