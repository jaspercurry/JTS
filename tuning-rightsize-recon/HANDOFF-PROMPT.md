## 5. Mechanics that cost us time (follow them)

- Agents share the scratchpad; every agent uses `mktemp -d` and its own
  worktree; commit with explicit paths, never `git add -A`.
- ≤6 full pytest lanes on the box at once; agents run only their touched
  modules' tests; CI is the authority.
- Sub-agents cannot fan out `/simplify`; their runs are single-pass. Run the
  full `/simplify` and `/code-review` yourself on the integration diff, and
  read the constants' comments against main — prose agents drop numeric
  couplings between constants and the review must catch them.
- Prose PRs: proof is a docstring-stripped AST compare against the branch's
  merge-base (`astsame.py`). Integration: merge docs → deletions → code →
  prose → tests; `-X ours` for prose/test branches, `-X theirs` for
  deletion branches, then hand-check every `-X` hunk (two of eleven needed
  it in wave 2).
- `main` moves under you: fetch before every branch, rebase before every
  push, refresh the exclusion list from open PRs' file lists at each wave.
- Commit footer and PR footer are mandatory (EXEC-W2.md has the exact text);
  no model identifiers in anything pushed.
- Never loop `tests/voice_eval/` (paid). Never deploy from an agent.
- Report to the owner in plain language, evidence first, one recommendation,
  the tradeoff stated; they decide.
